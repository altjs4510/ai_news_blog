## 📌 학습 정리

### 1. 한 줄로 말하면

코드를 고친 내역을 AI가 대신 꼼꼼히 검토해 주는 도구예요. "어떤 파일을 볼지" 같은 틀리면 안 되는 일은 정해진 규칙이 맡고, "이 코드가 왜 문제인지" 같은 판단은 AI가 맡도록 일을 나눴어요.

### 2. 왜 이게 만들어졌어요?

요즘은 Claude Code 같은 범용 AI 도우미에게 코드 검토를 맡기는 경우가 많아요. 그런데 고친 파일이 많아지면 AI가 일부 파일만 보고 나머지를 건너뛰거나, 문제라고 짚은 줄 번호가 실제 위치와 어긋나는 일이 자주 생겼다고 해요. 지시문을 조금만 바꿔도 검토 품질이 크게 흔들려서 원인을 찾기도 어려웠고요. 원문은 그 이유를 "말로만 지시하는 구조라서 검토 과정을 강제로 붙잡아 줄 장치가 없다"고 봐요. 이 도구는 원래 알리바바 그룹 안에서 쓰던 공식 AI 코드 검토 도우미였어요. 2년 동안 수만 명의 개발자가 썼고 수백만 건의 코드 결함을 찾아냈다고 하는데, 그렇게 큰 규모에서 검증한 뒤 누구나 쓸 수 있게 공개한 거예요.

### 3. 비유로 풀면

출판사 교정 작업에 비유할 수 있어요. 편집장이 원고 목록을 보고 "이번에 바뀐 장은 이것들이고, 1장과 1장 부록은 같이 봐야 한다"고 묶음을 나눠요. 그리고 묶음마다 "이 장은 맞춤법, 저 장은 인용 출처를 중점적으로 봐 주세요" 하는 체크리스트를 붙여서 교정자 여러 명에게 나눠 줘요. 교정자는 필요하면 원고 전체나 다른 장을 찾아보면서 판단하고요. 마지막에는 별도 담당자가 "지적한 쪽수가 맞는지, 지적 내용이 타당한지" 한 번 더 확인해요.

그래서 결국… 목록 정리, 묶음 나누기, 체크리스트 배정, 쪽수 확인은 규칙대로 돌아가는 프로그램이 하고, 실제로 읽고 판단하는 교정자 역할만 AI가 맡는 구조예요.

### 4. 어떻게 작동하는지 (그림으로)

```mermaid
flowchart TD
    A[Git에서 바뀐 내역 읽기] --> B[검토할 파일 정확히 고르기<br/>불필요한 파일은 걸러냄]
    B --> C[관련 파일끼리 묶음 만들기<br/>예: 영어·중국어 메시지 파일]
    C --> D[파일 특성에 맞는 검토 규칙 붙이기]
    D --> E1[묶음 1 담당 AI]
    D --> E2[묶음 2 담당 AI]
    D --> E3[묶음 N 담당 AI]
    E1 & E2 & E3 --> F[필요하면 도구 사용<br/>파일 전체 읽기 · 코드 검색 · 다른 변경 파일 확인]
    F --> G[코멘트 위치 바로잡기 + 내용 다시 점검]
    G --> H[줄 단위로 정리된 검토 결과]
```

위쪽의 파일 고르기, 묶기, 규칙 붙이기는 AI 없이 프로그램 로직이 처리해요. 그다음 묶음마다 독립된 AI가 따로 붙어서 동시에 검토하는데, 서로 맥락이 섞이지 않아서 바뀐 파일이 아주 많아도 안정적으로 돌아간다고 해요. 마지막으로 코멘트 위치와 내용을 점검하는 별도 모듈을 거친 뒤 결과가 나와요.

### 5. 처음 보는 용어 풀이

- **결정론적 처리 (deterministic)** — 같은 입력을 넣으면 매번 똑같은 결과가 나오는 방식이에요. AI처럼 그때그때 답이 달라지지 않아서, 절대 틀리면 안 되는 단계를 이런 방식으로 처리해요.
- **바뀐 내역 (diff)** — 코드의 이전 버전과 지금 버전을 비교해서 달라진 부분만 뽑아 놓은 거예요. 이 도구는 기본적으로 이걸 읽어서 검토를 시작해요.
- **도구를 쓸 줄 아는 AI 도우미 (agent with tool use)** — 주어진 글만 읽고 답하는 게 아니라, 필요할 때 파일을 열어 보거나 코드를 검색하는 등 스스로 행동하면서 일하는 AI예요. 바뀐 부분만 겉핥기로 보지 않고 주변 맥락까지 찾아볼 수 있어요.
- **하위 도우미 (sub-agent)** — 큰 일을 나눠서 각 조각을 따로 맡는 작은 AI 도우미예요. 묶음마다 하나씩 붙고 서로 맥락이 분리되어 있어서 동시에 돌릴 수 있어요.
- **정밀도 / 재현율 / F1 (Precision / Recall / F1)** — 정밀도는 "AI가 문제라고 한 것 중 진짜 문제의 비율", 재현율은 "진짜 문제 중 AI가 찾아낸 비율"이에요. F1은 둘을 합쳐 전체 품질을 숫자 하나로 보여 줘요.
- **토큰 (token)** — AI가 글을 읽고 쓸 때 쓰는 단위예요. 많이 쓸수록 API 비용이 늘어나서, 이 도구는 범용 AI 대비 약 9분의 1만 쓴다는 점을 강조해요.
- **위임 모드 (Delegation Mode)** — 파일 고르기와 규칙 정리는 이 도구가 하고, 실제 검토는 내가 이미 쓰고 있는 AI 코딩 도우미에게 맡기는 방식이에요. 이 모드에서는 이 도구에 AI 모델 연결을 따로 설정하지 않아도 돼요.

참고로 벤치마크 결과를 보면 같은 모델을 썼을 때 범용 AI보다 정밀도와 F1은 꽤 높지만 재현율은 더 낮아요. 쓸데없는 경고로 시간을 뺏지 않으려고 일부러 그쪽을 택했다고 설명해요. 이 비교는 인기 오픈소스 저장소 50곳의 실제 코드 변경 요청 200건(10개 언어)을 바탕으로 했고, 80명이 넘는 시니어 엔지니어가 정답 문제 1,505건을 교차 검증했어요.

### 6. 한 발 더 들어가고 싶다면

- [alibaba/open-code-review](https://github.com/alibaba/open-code-review) — 이걸 보면 설치 명령(`npm install -g @alibaba-group/open-code-review`), 기본 사용법(`ocr review`, 파일 전체를 검토하는 `ocr scan`), 벤치마크 설명을 원문 그대로 확인할 수 있어요.
- [open-codereview.ai/docs](https://open-codereview.ai/docs) — 이걸 보면 검토 규칙을 내 입맛에 맞게 바꾸는 방법, Claude Code·Codex·Cursor 같은 AI 코딩 도구와 연결하는 방법, GitHub Actions 같은 자동 빌드 환경에 붙이는 방법을 알 수 있어요.

## Open Code Review란 무엇인가?

Open Code Review는 AI 기반 코드 리뷰 CLI 도구다. 이 도구는 Alibaba Group 내부의 공식 AI 코드 리뷰 어시스턴트로 출발했다 — 지난 2년간 수만 명의 개발자에게 서비스를 제공했고 수백만 건의 코드 결함을 찾아냈다. 대규모로 충분히 검증을 거친 뒤, 우리는 이를 커뮤니티를 위한 오픈소스 프로젝트로 인큐베이션했다. 모델 엔드포인트만 설정하면 바로 시작할 수 있다.

이 도구는 Git diff를 읽고, 변경된 파일을 도구 사용(tool-use) 기능을 갖춘 에이전트를 통해 설정 가능한 LLM에 전달하며, 라인 단위의 정밀도를 가진 구조화된 리뷰 코멘트를 생성한다. 에이전트는 전체 파일 내용을 읽고, 코드베이스를 검색하고, 다른 변경된 파일을 맥락 파악을 위해 확인할 수 있어, 단순한 표면적 diff 피드백이 아니라 깊이 있는 리뷰를 만들어낸다. diff 리뷰를 넘어, `ocr scan`은 낯선 코드베이스나 의미 있는 diff가 없는 디렉토리를 감사(auditing)하기 위해 전체 파일을 리뷰한다.

자세한 내용은 [공식 웹사이트](https://open-codereview.ai)를 방문하라.

## 벤치마크

동일한 기반 모델을 사용했을 때, Open Code Review는 범용 에이전트(Claude Code)와 비교해 **Precision**과 **F1**에서 유의미하게 더 높은 성능을 달성하는 한편, 토큰 소비량은 **약 1/9**에 불과하고 리뷰 완료 속도도 더 빠르다. 다만 Recall은 범용 에이전트보다 낮다는 점에 유의해야 한다 — 이는 노이즈보다 정밀도(precision)를 우선하기 위한 의도적인 트레이드오프다.

50개의 인기 오픈소스 저장소, 200개의 실제 Pull Request, 10개의 프로그래밍 언어로 구성된 실전 코드 리뷰 벤치마크이며, 80명 이상의 시니어 엔지니어가 교차 검증했다(1,505건의 주석 처리된 정답(ground-truth) 이슈).

[Hugging Face에서 AACR-Bench 데이터셋을 살펴보라](https://huggingface.co).

| 지표 | 측정하는 것 | 중요한 이유 |
|---|---|---|
| F1 | Precision과 Recall의 조화평균 | 전반적인 리뷰 품질을 나타내는 최적의 단일 수치 |
| Precision | 보고된 이슈 중 실제 결함인 비율 | 높을수록 걸러내야 할 오탐(false alarm)이 적음 |
| Recall | 실제 결함 중 발견된 비율 | 높을수록 리뷰에서 빠뜨리는 이슈가 적음 |
| Avg Time | 리뷰 1건당 실제 소요 시간(wall-clock time) | CI 파이프라인 지연에 영향을 미침 |
| Avg Token | 리뷰 1건당 소비되는 총 토큰 수 | API 비용에 직접적인 영향을 미침 |

## Open Code Review를 쓰는 이유

### 범용 에이전트의 문제점

Skills와 함께 Claude Code 같은 범용 에이전트를 코드 리뷰에 써본 적이 있다면, 다음과 같은 고충을 겪었을 가능성이 높다:

- **불완전한 커버리지** — 규모가 큰 변경 세트에서는 에이전트가 "대충 넘어가는" 경향을 보이며, 일부 파일만 선택적으로 리뷰하고 나머지는 놓친다.
- **위치 드리프트(Position drift)** — 보고된 이슈가 실제 코드 위치와 일치하지 않는 경우가 잦으며, 라인 번호나 파일 참조가 목표에서 벗어난다.
- **불안정한 품질** — 자연어 기반으로 구동되는 Skills는 디버그하기 어렵고, 프롬프트의 사소한 변화만으로도 리뷰 품질이 크게 요동친다.

근본 원인은 다음과 같다: 순수하게 언어로 구동되는 아키텍처는 리뷰 과정에 대한 엄격한 제약(hard constraint)이 없다.

### 핵심 설계: 결정론적 엔지니어링 × 에이전트 하이브리드

Open Code Review의 핵심 철학은 결정론적 엔지니어링(deterministic engineering)과 에이전트를 결합해, 각각이 가장 잘하는 일을 맡도록 하는 것이다.

#### 결정론적 엔지니어링 — 엄격한 제약

**절대 잘못되어서는 안 되는** 리뷰 단계에 대해서는, 언어 모델이 아니라 엔지니어링 로직이 정확성을 보장한다:

- **정밀한 파일 선정** — 어떤 파일을 리뷰해야 하고 어떤 파일을 걸러내야 하는지 정확히 결정하여, 중요한 변경 사항이 누락되지 않도록 보장한다.
- **스마트한 파일 번들링** — 관련된 파일들을 하나의 리뷰 단위로 묶는다(예: `message_en.properties`와 `message_zh.properties`가 함께 번들링된다). 각 번들은 격리된 컨텍스트를 가진 서브 에이전트로 실행되며 — 매우 큰 변경 세트에서도 안정성을 유지하고 동시 리뷰를 자연스럽게 지원하는 분할 정복(divide-and-conquer) 전략이다.
- **세밀한 규칙 매칭** — 각 파일의 특성에 맞춰 리뷰 규칙을 매칭하여, 모델의 주의를 날카롭게 집중시키고 정보 노이즈를 원천에서 제거한다. 순수하게 언어로 구동되는 규칙 안내와 비교해, 템플릿 엔진 기반의 규칙 매칭이 더 안정적이고 예측 가능하다.
- **외부 위치 지정 및 반영(reflection) 모듈** — 독립적인 코멘트 위치 지정 모듈과 코멘트 반영 모듈이 AI 피드백의 위치 정확도와 내용 정확도를 체계적으로 향상시킨다.

#### 에이전트 — 동적 의사결정

에이전트의 강점은 가장 중요한 부분, 즉 동적 의사결정과 동적 컨텍스트 검색에 집중되어 있다:

- **시나리오 맞춤형 프롬프트** — 코드 리뷰에 맞춰 깊이 최적화된 프롬프트 템플릿으로, 효과를 높이는 동시에 토큰 소비를 줄인다.
- **시나리오 맞춤형 툴셋** — 대규모 프로덕션 데이터의 도구 호출 트레이스(tool-call trace)를 심층 분석하여 정제해 냈다 — 호출 빈도 분포, 도구별 반복률, 신규 도구가 전체 호출 체인에 미치는 영향 등을 포함한다. 그 결과 범용 에이전트 툴킷보다 코드 리뷰에 더 안정적이고 예측 가능한 전용 툴셋이 탄생했다.

## 사용 방법

### 사전 요구사항

- **Git >= 2.41** — Open Code Review는 diff 생성, 코드 검색, 저장소 작업을 위해 Git에 의존한다.

### CLI

#### 설치

```
npm install -g @alibaba-group/open-code-review
```

설치 후, `ocr` 명령어를 전역에서 사용할 수 있다.

다른 설치 방법(설치 스크립트, GitHub Release 바이너리, 소스로부터 빌드)은 [Installation](https://open-codereview.ai/docs/installation)을 참고하라.

### 빠른 시작

#### 1. LLM 설정

**Delegation Mode**를 사용하지 않는 한, 코드를 리뷰하기 전에 반드시 LLM을 설정해야 한다.

```
ocr config provider
# 내장 provider를 선택하거나 커스텀 provider를 추가
ocr config model
# 활성화된 provider에 대한 모델을 선택
```

대화형 UI가 provider 선택, API 키 입력, 모델 설정을 안내한 뒤, 자동으로 연결 테스트를 수행한다.

CLI 설정, 환경 변수, 커스텀 provider 및 기타 고급 설정은 [Configuration](https://open-codereview.ai/docs/configuration)을 참고하라.

#### 2. 리뷰

```
cd your-project

# Workspace 모드 — staged, unstaged, untracked 변경 사항을 모두 리뷰
ocr review

# 브랜치 범위 — feature-branch가 main에서 갈라진 이후의 변경 사항을 리뷰(merge-base 모드)
ocr review --from main --to feature-branch

# 단일 커밋
ocr review --commit abc123

# 중단된 범위 또는 커밋 리뷰를 재개
ocr session list
ocr review --from main --to feature-branch --resume <session-id>

# 전체 파일 스캔 — diff 대신 전체 파일을 리뷰(git 히스토리 불필요)
ocr scan
# 저장소 전체를 스캔
ocr scan --path internal/agent
# 디렉토리 또는 특정 파일을 스캔
ocr scan --resume <session-id>
# 중단된 전체 파일 스캔을 재개

# 결과를 파일로 저장(AI 호스트 에이전트에 권장)
ocr review --format json --output result.json

# Delegation 모드 — AI 코딩 에이전트가 직접 리뷰를 수행하도록 위임
# OCR은 파일 선정과 규칙 해석만 처리, LLM 설정 불필요
ocr delegate preview
ocr delegate rule src/main.go src/handler.go
```

- [Configuration](https://open-codereview.ai/docs/configuration) — 설정 키와 환경 변수
- [MCP Server](https://open-codereview.ai/docs/mcp-server) — 외부 도구로 리뷰 에이전트 확장
- Coding Agent Integrations — 사용하는 플랫폼 선택
  - [Claude Code](https://open-codereview.ai/docs/integrations/claude-code) — 리뷰 슬래시 명령어가 포함된 플러그인 설치
  - [Codex](https://open-codereview.ai/docs/integrations/codex) — 호출 가능한 리뷰 스킬이 포함된 플러그인 설치
  - [Cursor](https://open-codereview.ai/docs/integrations/cursor) — 이식 가능한 리뷰 스킬이 포함된 플러그인 설치
  - [OpenCode](https://open-codereview.ai/docs/integrations/opencode) — 네이티브 리뷰 도구와 슬래시 명령어 설치
  - [QCA Forward](https://open-codereview.ai/docs/integrations/qca-forward) — QCA 호스트 모델과 바로 게시 가능한 템플릿으로 delegation 모드 실행
  - [Skill-compatible agents](https://open-codereview.ai/docs/integrations/skill-compatible-agents) — 이식 가능한 에이전트 스킬 설치
- Review Execution Modes — 연동 후, 어떤 LLM이 리뷰를 수행할지 선택
  - **Default (OCR-managed)** — OCR이 설정된 자체 LLM으로 리뷰를 실행
  - **Delegation Mode** — 사용자의 코딩 에이전트가 자체 LLM으로 리뷰를 실행, OCR API 키 불필요
- [CI/CD Integration](https://open-codereview.ai/docs/ci-cd) — GitHub Actions, GitLab CI, GitFlic CI, Gerrit 연동
- [Session Viewer](https://open-codereview.ai/docs/session-viewer) — 브라우저에서 리뷰 세션을 탐색·재생하고, 코멘트를 수정됨/무시됨으로 표시하여 이슈를 처리하는 동안 숨기기
- [Telemetry](https://open-codereview.ai/docs/telemetry) — 관찰가능성(observability)을 위한 OpenTelemetry 연동
- [FAQ](https://open-codereview.ai/docs/faq) — 자주 묻는 질문 및 문제 해결
