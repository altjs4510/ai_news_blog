### 2. 왜 이게 만들어졌어요?

명령줄 도구(터미널)에서 코딩 도우미를 쓰면, 그 도구가 분석하고 정리한 내용은 보통 화면에 텍스트로만 남아요. 동료에게 결과를 공유하려면 따로 문서를 만들거나, 회의 시간에 "지금까지 뭘 찾았는지 설명해줘" 하고 다시 정리해 줘야 했죠. 장애 대응이나 코드 리뷰처럼 여러 사람이 같이 봐야 하는 상황에서는, 작업하는 시간보다 상황을 설명하는 시간이 더 길어지기도 합니다. 이런 "상황 공유 비용"을 줄이려고, 작업 결과물 자체를 공유 가능한 페이지로 바로 뽑아내는 방식이 만들어졌어요.

### 3. 비유로 풀면

이건 마치 요리하는 동안 주방 옆 모니터에 진행 상황이 실시간으로 떠 있는 것과 비슷해요. 손님은 "지금 뭐 만드는 중이에요?" 하고 물어볼 필요 없이 화면만 보면 되고, 새 재료가 들어가면 화면도 같이 바뀝니다. 그래서 결국, 작업하는 사람과 지켜보는 사람이 같은 그림을 동시에 보게 되어 따로 설명하는 단계가 줄어드는 거예요.

### 4. 어떻게 작동하는지 (그림으로)

```mermaid
flowchart TD
    A[터미널에서 코딩 도우미와 작업] --> B[세션 맥락 모으기<br/>코드, 연결된 도구, 대화 내용]
    B --> C[산출물(artifact) 페이지 생성]
    C --> D[같은 링크로 팀원에게 공유]
    A -.작업 진행.-> E[페이지 자동 갱신]
    E --> F[버전 기록 남김<br/>이전 버전으로 되돌리기 가능]
```

세션에서 다루던 코드, 외부에서 끌어온 데이터, 대화 내용을 모아서 하나의 웹페이지로 묶어요. 작업이 진행되면서 같은 주소(URL)에 새 버전이 계속 덮여 쓰이고, 동료가 그 링크를 열어두면 자동으로 최신 내용이 보입니다. 이전 버전 기록도 남아 있어서 필요하면 되돌릴 수 있어요.

### 5. 처음 보는 용어 풀이

- **산출물 (artifact)** — 코딩 세션의 결과를 담은 공유 가능한 웹페이지예요. 글로 정리된 보고서가 아니라 클릭하고 필터링할 수 있는 살아있는 페이지라는 점이 특징입니다.
- **클로드 코드 (Claude Code)** — 터미널이나 데스크톱 앱에서 코드를 같이 짜고 분석해 주는 코딩 도우미 도구예요. 이번 기능은 이 도구 안에서 동작합니다.
- **세션 맥락 (session context)** — 한 번의 작업 동안 코딩 도우미가 들고 있는 정보 묶음을 말해요. 어떤 코드 저장소를 보고 있었는지, 어떤 외부 도구가 연결돼 있는지, 무슨 대화를 나눴는지 같은 것들이 다 포함됩니다.
- **연결자 (connector)** — 코딩 도우미가 외부 서비스(예: 모니터링 도구, 문서 저장소 등)에서 데이터를 가져올 수 있게 이어주는 통로예요. 산출물이 외부 데이터까지 한 페이지에 모아 보여줄 수 있는 건 이 연결자 덕분입니다.
- **풀 리퀘스트 워크스루 (PR walkthrough)** — 코드 변경 묶음을 리뷰어가 따라가기 쉽게 정리한 안내 페이지예요. 어떤 부분을 왜 바꿨는지, 어떻게 테스트했는지 흐름대로 보여줍니다.
- **포스트모템 (postmortem)** — 장애가 끝난 뒤 무슨 일이 있었고 왜 그랬는지 정리한 사후 보고서예요. 산출물 기능을 쓰면 조사하던 페이지가 그대로 사후 보고서로 이어질 수 있다고 합니다.
- **컴플라이언스 API (compliance API)** — 조직 차원에서 누가 무엇을 만들고 봤는지 점검할 수 있게 해주는 관리자용 인터페이스예요. 관리자는 이걸로 조직 전체의 산출물 사용 현황을 들여다볼 수 있습니다.

### 6. 한 발 더 들어가고 싶다면

- [산출물 시작 가이드](http://code.claude.com/docs/en/artifacts) — 실제로 어떻게 켜고 쓰는지, 어떤 명령으로 페이지를 만들 수 있는지 확인할 수 있어요.
- [Claude Code 제품 페이지](https://claude.com/product/claude-code) — 이번 기능이 얹힌 본체 도구가 무엇이고 어떤 환경에서 돌아가는지 전반을 볼 수 있어요.
- [Claude Code의 routines 소개 글](https://claude.com/blog/introducing-routines-in-claude-code) — 산출물과 함께 쓰면 좋은 자동화 흐름 기능을 알 수 있어요.
- [MCP 연결자 권한 중앙 관리](https://claude.com/blog/enterprise-managed-auth) — 외부 도구를 산출물에 끌어다 쓸 때 조직 차원에서 접근 권한을 어떻게 관리하는지 흐름을 잡을 수 있어요.

> 의역 최소화한 전체 번역입니다. 큰 흐름은 위 정리에서 잡고, 정확한 워딩이 필요할 땐 이 섹션에서 정독하세요.

# Claude Code, 이제 아티팩트(Artifacts)를 지원합니다

_진행 중인 작업을 라이브 대화형 웹 페이지로 미리 보기—전체 세션 컨텍스트를 바탕으로 구축되며 팀과 공유 가능합니다._

- **카테고리:** 제품 발표 (Product announcements)
- **제품:** Claude Code
- **날짜:** 2026년 6월 18일
- **읽기 소요 시간:** 5분

오늘부터 Claude Code는 작업 진행 상황을 아티팩트로 캡처할 수 있습니다. 아티팩트는 Claude Code의 작업물을 라이브로 공유 가능한 시각적 페이지—PR 워크스루(walkthrough), 시스템 설명서, 대시보드, 릴리스 체크리스트 등—로 변환하며, 세션이 진행되는 동안 스스로 업데이트됩니다.

Claude Code 세션은 인시던트 조사부터 서비스 리팩터링, 수개월치 데이터 분석까지 다양한 범위를 아우릅니다. 아티팩트는 그 작업 내용을 누구나 열어서 탐색할 수 있는 웹 페이지로 변환합니다. 예를 들어 풀 리퀘스트(pull request) 워크스루, 필터·정렬이 가능한 대시보드, 심지어 작업이 완료됨에 따라 자동으로 채워지는 릴리스 체크리스트도 만들 수 있습니다. 아티팩트는 공유 작업에서의 협업을 더 쉽게 만들어, 팀이 상태 업데이트를 전달하는 데 쓰는 시간을 줄이고 실제 개발에 더 많은 시간을 투자할 수 있도록 합니다.

---

## **세션 컨텍스트 위에 구축**

Claude Code는 코드베이스, 커넥터(connectors), 그리고 대화 자체를 포함한 세션의 전체 컨텍스트를 활용하여 아티팩트를 구축합니다. 하나의 인시던트 페이지에 코드에서 실패한 테스트와 그 배경이 된 함수, 연결된 모니터링 툴의 오류 급증 데이터, 방금 실행한 세션의 근본 원인 분석 내용을 모두 담을 수 있습니다. 아티팩트를 사용하면 별도로 데이터 소스를 연결하거나 인프라를 구축할 필요가 없습니다. 페이지를 요청하면 Claude Code가 이미 존재하는 것들을 바탕으로 만들어 줍니다.

---

## **실시간으로 업데이트되는 라이브 페이지**

Claude Code가 아티팩트를 업데이트하면, 열려 있는 페이지가 제자리에서 새로 고쳐지며 팀원들은 업데이트가 게시되는 즉시 변경 사항을 확인할 수 있습니다. 모든 게시는 동일한 링크에서 새 버전으로 기록되며, 언제든지 복원할 수 있는 버전 이력이 남습니다. 또한 갤러리 기능을 통해 생성한 모든 아티팩트를 탐색하고 관리할 수 있습니다.

내부 테스트에서 가장 일반적인 사용 사례 중 하나는 디버깅이었습니다. 전형적인 시나리오는 다음과 같습니다: 엔지니어가 스탠드업(standup) 전에 인시던트 조사를 시작합니다. Claude Code가 로그를 분석하고 타임라인, 의심스러운 커밋, 오류율 차트가 담긴 아티팩트를 게시합니다. 엔지니어는 페이지 헤더에서 팀에 링크를 공유합니다. 스탠드업이 시작될 때쯤이면 조사가 진행됨에 따라 Claude가 최신 정보를 반영하여 이미 두 차례 재게시한 상태입니다. 아티팩트 덕분에 팀원과 이해관계자들이 "에이전트가 발견한 것을 설명해 달라"고 요청할 필요가 없습니다. 모두가 동일한 컨텍스트로 동일한 화면을 보고 있기 때문입니다.

---

## **조직 내부에서만 비공개 공유**

모든 아티팩트는 기본적으로 작성자만 볼 수 있습니다. 준비가 되면 페이지에서 직접 팀원 및 조직과 공유할 수 있습니다. 아티팩트는 조직의 인증된 멤버만 볼 수 있으며, 외부 공개는 불가능합니다. 관리자는 조직 수준의 토글(toggle)과 역할 기반 범위 설정으로 접근을 관리하고, 보존 정책을 설정하며, 컴플라이언스 API(compliance API)를 통해 조직 전체의 현황을 파악할 수 있습니다.

---

## **시작하기**

세션에 아티팩트를 요청하거나, 시각적인 결과물을 달라고 해보세요. _역할별 아이디어는 다음과 같습니다:_

- **법무 / 오픈 소스**: 저작권이 있는 라이선스를 표시하며, 레포지토리에서 바로 모든 의존성에 대한 라이선스 감사 수행.
  _"모든 서드파티 의존성과 해당 라이선스를 나열하고, 카피레프트(copyleft)에 해당하는 항목을 표시하는 아티팩트를 만들어 줘."_

- **개인정보 보호**: 코드 전반에 걸쳐 개인 데이터가 수집, 저장, 기록되는 위치에 대한 데이터 흐름 맵.
  _"개인 데이터를 다루는 부분을 코드베이스 전체에 걸쳐 추적하여 개인정보 보호 검토용 아티팩트로 만들어 줘."_

- **보안**: 정확한 코드 라인에 연결되어 수정이 명확하게 이루어질 수 있는 조사 결과.
  _"이번 검토에서 발견된 인증(auth) 관련 문제들을 각각 해당 코드와 연결한 아티팩트로 만들어 줘."_

- **FinOps / 플랫폼 재무**: 인프라 코드(Infrastructure-as-Code)에서 매핑된 클라우드 리소스와 비용 유발 요인.
  _"Terraform에서 클라우드 리소스를 서비스별로 그룹화하고 주요 비용 유발 요인을 포함한 아티팩트로 만들어 줘."_

- **소프트웨어 엔지니어**: 리뷰어가 실제로 따라올 수 있는 PR 또는 버그 워크스루로, diff와 주변 코드에서 추출.
  _"이 PR—diff, 개발 이유, 테스트한 내용—을 설명하는 아티팩트를 만들어 줘."_

- **디자이너 & 프론트엔드 엔지니어**: 실제 컴포넌트로 구축된 여러 UX 방향안으로, 선택한 안을 바로 배포할 수 있음.
  _"우리 컴포넌트 라이브러리를 기반으로 이 회원가입 폼의 UX 변형안 5개를 담은 아티팩트를 만들어 줘."_

- **스태프 엔지니어 & 아키텍트**: 화이트보드가 아닌 실제 임포트 그래프에서 그려낸 서비스 구조 맵.
  _"코드에서 결제(payments) 서비스가 어떻게 구성되어 있는지 아티팩트로 매핑해 줘."_

- **SRE & 온콜(on-call)**: 조사가 진행되면서 내용이 쌓이고 포스트모텀(postmortem)으로 발전하는 인시던트 페이지.
  _"이 인시던트를 아티팩트로 만들어 줘—타임라인, 의심 커밋, 모니터링에서 나온 오류 급증 내용을 담아서—그리고 내가 조사를 진행하는 동안 재게시해 줘."_

- **엔지니어링 매니저**: 머지된 PR에서 구축한, 실제로 릴리스된 내용이 담긴 페이지.
  _"이번 주 우리 팀에서 머지된 PR들을 프로젝트별로 그룹화한 아티팩트를 만들어 줘."_

Claude Code가 페이지를 구축하고 링크를 제공합니다. 브라우저나 데스크탑 앱에서 열고, 헤더에서 공유하세요—업데이트는 동일한 URL에 자동으로 게시됩니다.
