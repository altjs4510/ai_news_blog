## 📌 학습 정리

### 1. 한 줄로 말하면

며칠씩 걸리는 일을 맡겨도 중간에 잊어버리지 않고 계속 굴러가는 코딩·리서치 조수예요. 게다가 일을 하면서 "다음엔 이렇게 하자"는 메모를 스스로 남겨 조금씩 나아집니다.

### 2. 왜 이게 만들어졌어요?

지금까지 대화형 AI 조수는 대체로 "한 번 물어보고 한 번 답 받는" 방식에 최적화돼 있었어요. 그런데 실제 개발이나 연구 업무는 몇 시간, 며칠씩 이어지는 경우가 많고, 그 사이에 대화창을 닫거나 터미널 연결이 끊기면 그동안 쌓인 맥락이 통째로 날아갑니다. 같은 설명을 매번 다시 해야 하고, 지난번에 통했던 방식도 다음 세션에서는 남아 있지 않죠. Prime Agent는 이 지점을 정면으로 잡아서, 작업 중에 쌓인 맥락과 반복해서 쓰는 작업 패턴이 하나의 대화창보다 오래 살아남게 만드는 걸 목표로 합니다. 그래서 "오래 도는 일(long-running work)", 특히 연구에서의 평가 작업을 전제로 설계했다고 밝히고 있어요.

### 3. 비유로 풀면

이건 마치 **프로그램을 종료하지 않은 계산기 화면**과 비슷해요. 보통은 매번 처음부터 숫자를 다시 입력해야 하는데, 여기서는 앞서 계산한 값이 변수로 남아 있어서 "아까 그 값"을 그대로 다음 계산에 쓸 수 있습니다. Prime Agent도 대화 맥락을 글자 덩어리가 아니라 프로그램 안의 변수처럼 다뤄요.

또 하나는 **일하면서 업무 노트를 계속 고쳐 쓰는 신입 동료**예요. 오늘 부딪힌 문제와 해결한 방식을 노트에 짧게 적어두고, 다음에 비슷한 일이 오면 그 노트를 먼저 펼쳐 봅니다. 다만 회사의 기본 규정집은 함부로 고치지 않고, 자기 노트만 조심스럽게 다듬죠.

그래서 결국, 맥락을 붙잡아 두는 방식(변수처럼 보관)과 경험을 쌓는 방식(고쳐 쓰는 노트)을 둘 다 코드 수준에서 구현해 놓은 도구라고 보면 됩니다.

### 4. 어떻게 작동하는지 (그림으로)

```mermaid
flowchart TD
    A[사용자가 목표를 준다] --> B[살아있는 파이썬 실행창<br/>맥락을 변수로 보관]
    B --> C{일을 어떻게 나눌까}
    C -->|직접 처리| D[파일 수정·명령 실행<br/>모두 코드로]
    C -->|나눠서 처리| E[새끼 에이전트 여러 개<br/>병렬·백그라운드 작업]
    E --> F[결과를 값으로 돌려받음]
    D --> F
    F --> G[진행 상황 정리·압축<br/>목표는 계속 유지]
    G -->|아직 남음| B
    G -->|되돌아보기| H[스스로 다듬기<br/>근거 있는 작은 메모만 저장]
    H --> I[다음 세션에도 남는<br/>보조 지침·기억·재사용 기술]
    I --> B
    B -.터미널 꺼져도 계속.-> J[백그라운드 상주 프로세스<br/>나중에 다시 접속]
```

핵심은 모든 동작이 "코드"로 일어난다는 점이에요. 파일을 고치든, 명령을 돌리든, 도우미 에이전트를 부르든 전부 파이썬 코드 호출로 처리되고, 그 결과도 값으로 돌아옵니다. 그리고 작업이 한 바퀴 돌 때마다 배운 것을 작은 메모로 남길 수 있는데, 이 메모는 다음 세션에도 살아남아 다시 참고됩니다.

### 5. 처음 보는 용어 풀이

- **재귀 언어 모델 (Recursive Language Model, RLM)** — 대화 맥락을 통째로 밀어 넣는 대신 프로그램 속 변수처럼 다루고, 도우미 에이전트를 함수 호출하듯 부르는 방식이에요. 덕분에 큰 작업을 잘게 쪼개 다루기가 수월해집니다.
- **지속형 실행창 (persistent IPython) 
** — 대화가 이어지는 동안 꺼지지 않고 유지되는 파이썬 실행 환경이에요. 앞에서 만든 값이 그대로 남아 있어서, 다음 단계에서 재사용할 수 있습니다.
- **이어지는 작업틀 (Continual Harness)** — 보조 지침, 기억, 재사용 가능한 기술 설명 등을 세션이 끝나도 남는 상태로 저장해 두는 공간이에요. 여기에 쌓인 내용을 조금씩 다듬어 나가는 게 "스스로 개선"의 실체입니다.
- **다듬기 명령 (/refine)** — 지금까지의 작업 흐름을 되돌아보고, 근거가 있는 작은 수정만 위 작업틀에 반영하는 기능이에요. 원문에 따르면 바꿀 수 없는 기본 시스템 지침은 절대 건드리지 않고, 변경 이력을 기록해 되돌리기도 가능합니다.
- **도우미 에이전트 (subagent)** — `rlm(...)` 호출로 만들어지는 자식 에이전트예요. 여러 갈래 작업을 나란히 돌리거나 백그라운드로 돌린 뒤, 그 결과를 값으로 받아 이어서 쓸 수 있습니다.
- **실행 가능한 기술 (skills)** — 자주 반복하는 작업 흐름을 파이썬 패키지 형태로 묶어 둔 것이에요. 설명만 적힌 문서가 아니라 실제로 불러다 쓸 수 있는 코드라는 점이 차이입니다.
- **상주 프로세스 기반 지속성 (daemon-backed continuity)** — 터미널 창을 닫아도 세션과 실행 상태, 예약된 일정, 도우미 에이전트가 계속 살아 있는 구조예요. 나중에 다시 붙어서(attach) 이어서 볼 수 있습니다.
- **한도 있는 자율 모드 (bounded autonomous mode)** — 턴 수, 토큰, 시간 예산 안에서 알아서 계속 진행하는 모드예요. 다만 원문은 "설정한 검사를 통과했다는 건 그 검사가 확인한 범위만 통과한 것이고, 한도에 도달했다고 해서 작업이 성공했다는 뜻은 아니다"라고 분명히 선을 긋고 있습니다.

한 가지 주의할 점도 원문이 직접 밝혀 둡니다. 이 도구는 모델이 만들어낸 파이썬 코드와 프로젝트 명령을 **사용자 권한 그대로** 실행하고, 내부의 작업자·커널 프로세스는 복구를 돕는 장치일 뿐 보안 격리 장치가 아니라고 해요. 그래서 신뢰할 수 있는 저장소에서만 쓰고, 언제든 되돌릴 수 있는 복사본이나 깨끗한 작업 폴더에서 돌리기를 권합니다.

# Prime Agent: 자가 개선형 RLM 에이전트

Documentation • Verifiers • PRIME-RL • pi-mono

Prime Agent는 범용 작업 및 장기 실행 작업을 위한 오픈소스 코딩·연구 에이전트다. 두 가지 핵심 추상화를 중심으로 설계되었다:

**Recursive Language Model (RLM)**는 컨텍스트를 변수로 취급(*prompt-as-a-variable*)하고, 재귀적 서브에이전트 같은 도구를 지속적인 REPL 내부의 함수 호출(*programmatic tool /sub-agent calling*)로 다룬다.

**Continual Harness**는 보조 프롬프트, 메모리, 스킬 설명, 재사용 가능한 서브에이전트 명세를 지속적인 상태(durable state)로 저장하며, Prime Agent는 이를 작고 근거에 기반한(evidence-backed) 업데이트를 통해 정련(refine)할 수 있다. 기본적으로 이는 세션에 로컬 범위로 한정된다.

Prime Agent는 지속적인 Python 제어 환경(persistent Python control environment)과 지속적인 harness 상태를 결합하여, 유용한 작업 컨텍스트와 재사용 가능한 운영 패턴이 하나의 채팅 창을 넘어 살아남을 수 있게 한다.

**모든 것이 프로그래밍적이다**: 지속적인 IPython이 내장 모델 도구이며, 파일 조작·셸 명령·도구 사용·서브에이전트·컨텍스트 관리가 모두 코드를 통해 이루어진다.

**서브에이전트가 내장되어 있다**: `rlm(...)`이 병렬 또는 백그라운드 작업을 위한 실제 자식 에이전트를 생성(spawn)하고 그 결과를 프로그래밍적으로 반환한다.

**harness는 개선될 수 있다**: `/refine`은 현재의 실행 궤적(trajectory)을 검토하고 보조 harness 상태에 작고 근거에 기반한 업데이트를 적용할 수 있다. 이는 불변(immutable)인 기본 시스템 프롬프트를 결코 다시 쓰지 않으며, 기록된 스냅샷이 롤백을 지원한다.

**스킬은 실행 가능하다**: 스킬은 임포트 가능한 Python 패키지이며, 내장된 스킬 생성기(skill creator)는 반복되는 워크플로우를 프로젝트 또는 개인 스킬로 전환할 수 있다.

**세션은 백그라운드에서 실행된다**: 데몬 기반 에이전트는 터미널 연결이 끊겨도 계속 실행되며, 나중에 다시 연결(reattach)할 수 있다.

**에이전트는 직접 통신한다**: 실행 중인 에이전트들은 모든 것을 사용자를 경유시키지 않고도 서로 메시지를 교환하고 서로를 오케스트레이션할 수 있다.

**장시간 작업은 계속 진행된다**: 자동 압축(compaction), 지속적인 목표(goal), 하트비트(heartbeat), 스케줄, 자율 모드(autonomous mode), 유지되는 서브에이전트가 여러 턴과 여러 터미널 세션에 걸쳐 진행 상황을 보존한다.

## 시작하기

macOS 또는 Linux에서 최신 안정 릴리스를 설치한다:

```
curl -fsSL https://app.primeintellect.ai/prime-agent/install.sh | sh
```

이 설치 프로그램은 버전이 지정된 릴리스를 다운로드하고, SHA-256 체크섬을 검증하며, `prime-agent` 명령을 설치하고, 에이전트가 사용하는 IPython 런타임을 준비할 수 있다.

작업하고자 하는 저장소 또는 디렉토리에서 Prime Agent를 시작한다:

```
cd /path/to/project
prime-agent
```

첫 실행 시 `/login`을 실행하여 구독 또는 API 키 제공자를 선택한다. Prime Agent는 현재 디렉토리에서 작동하며 그곳에서 명령을 실행하고 파일을 수정할 수 있다. 검토하고 복원할 수 있는 디스포저블(disposable) 클론, 클린 워크트리(worktree), 또는 그 밖의 체크포인트를 사용하라.

**경고**
Prime Agent는 모델이 생성한 Python 및 프로젝트 명령을 사용자의 권한으로 실행한다. 이 프로그램의 워커 및 커널 프로세스는 라이프사이클 격리와 복구를 개선하지만, 이는 보안 샌드박스가 **아니다**. 변경 사항을 검토하고, 신뢰할 수 있는 저장소·지시문·스킬·확장만 사용하라. 신뢰할 수 없는 코드나 지시문은 외부 샌드박스 또는 제한된 환경에서 실행하라.

유용한 명령들:

```
prime-agent agents                  # 실행 중, 유휴, 저장된 세션 탐색
prime-agent attach <agent>          # 실행 중인 세션에 다시 연결
prime-agent --resume <path|id>      # 저장된 세션 재개
prime-agent status                  # 백그라운드 서비스 상태 확인
prime-agent doctor [--fix]          # 백그라운드 서비스 확인 또는 복구
prime-agent update [--force]        # Prime Agent 업데이트
prime-agent shutdown [--force]      # 모든 에이전트, 워커, 백그라운드 서비스 정지
```

## 장시간 실행 작업을 위해 구축됨

Prime Agent는 장시간 실행 작업, 특히 연구 분야의 평가(evaluation) 작업을 위해 구축되었다. 다음 기능들은 TUI에서 사용 가능하며, 자율적으로 실행될 때도 사용 가능하다.

**Continual Harness**: `/refine`은 집중적이고 검토 가능한 교훈(lesson)을 보조 프롬프트, 메모리, 재사용 가능한 스킬 설명, 또는 서브에이전트 명세로 지속시킬 수 있으며, 정련(refinement) 이력이 기록된다. 이는 새로운 실행 가능한 스킬을 패키징하고 검토하는 것을 대체하지 않는다.

**직접적인 에이전트 간 통신**: 실행 중인 에이전트와 유지되는(retained) 서브에이전트는 서로를 발견하고, 메시지를 교환하며, 진행 중인 작업을 조율(steer)할 수 있다.

**데몬 기반 연속성**: 활성 세션, IPython 상태, 스케줄, 서브에이전트는 터미널이 분리(detach)되어도 계속 실행되며 나중에 다시 연결할 수 있다.

**하트비트와 스케줄**: `/heartbeat`, `rlm_heartbeat`, `prime-agent schedule`이 주기적으로 또는 특정 시각에 세션에 다시 진입할 수 있다.

**지속적인 목표(persistent goals)**: `/goal`은 목표와 그 진행 상황을 완료되거나, 일시정지되거나, 초기화될 때까지 여러 턴에 걸쳐 활성 상태로 유지한다.

**한계가 설정된 자율 모드(bounded autonomous mode)**: `/autonomous`는 설정된 턴, 토큰, 시간 예산 내에서 계속 진행하며 사용자가 정의한 품질 게이트(quality gate)를 실행할 수 있다. 통과한 게이트는 그 게이트가 검증하는 것만 확인하는 것이며, 한계에 도달했다는 것이 작업 성공을 의미하지는 않는다.
