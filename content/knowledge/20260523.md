## 📌 학습 정리

### 1. 한 줄로 말하면

코딩 도와주는 인공지능(AI) 비서가 매번 프로젝트 폴더를 뒤지느라 시간과 비용을 쓰지 않도록, 미리 코드 지도를 그려두고 필요한 곳만 콕 짚어 보여주는 도구예요.

### 2. 왜 이게 만들어졌어요?

요즘 클로드 코드(Claude Code)나 커서(Cursor) 같은 AI 코딩 도우미는 "이 기능이 어떻게 동작해?"라는 질문을 받으면, 폴더 안 파일들을 일일이 열어보고 텍스트 검색을 돌려가며 답을 찾아요. 큰 프로젝트일수록 이 탐색 과정에서 수많은 파일을 읽게 되고, 그만큼 토큰(token, AI가 처리하는 글자 단위로 비용의 기준이 됨)을 많이 써서 응답도 느려지고 돈도 더 들죠.

CodeGraph는 이걸 거꾸로 풀어요. 프로젝트를 처음에 한 번 훑어서 함수·클래스·호출 관계 같은 구조를 미리 데이터베이스로 만들어 두고, AI가 질문할 때 그 지도에서 바로 답을 꺼내 쓰게 해주는 거예요. 원문의 벤치마크에 따르면 평균적으로 비용은 35% 줄고, 도구 호출 횟수는 70% 줄었다고 해요.

### 3. 비유로 풀면

이건 마치 **낯선 도시에서 길을 찾는 두 가지 방법** 같아요. 한쪽은 골목마다 들어가서 간판을 하나씩 읽으며 헤매고(파일을 일일이 열어보는 방식), 다른 한쪽은 잘 정리된 지도와 색인을 먼저 펼쳐 보고 목적지를 찍는 거예요(미리 만들어둔 지식 그래프를 조회).

또 다른 비유로는, 책 한 권의 **맨 뒤에 붙어 있는 색인(index)** 같은 거예요. 본문을 처음부터 끝까지 읽지 않아도 "이 단어는 47쪽, 132쪽에 있다"고 바로 알려주죠. 그래서 결국 CodeGraph가 하는 일은 — AI에게 "코드베이스의 색인 페이지"를 미리 만들어 건네주는 거예요.

### 4. 어떻게 작동하는지 (그림으로)

```mermaid
flowchart TD
    A[개발자가 AI 코딩 도우미에게 질문<br/>'로그인 기능이 어떻게 동작해?'] --> B{프로젝트에<br/>코드 지도가 있나?}
    B -->|없음| C[AI가 파일을 하나씩 열어보고<br/>텍스트 검색을 반복<br/>→ 토큰·시간 많이 소비]
    B -->|있음| D[AI가 코드 지도에 질문<br/>'login과 관련된 부분 알려줘']
    D --> E[지식 그래프 데이터베이스<br/>함수·호출관계·파일 위치를<br/>이미 정리해둠]
    E --> F[관련 코드 조각만<br/>한 번에 묶어서 반환]
    F --> G[AI가 바로 답변<br/>→ 적은 호출, 빠른 응답]
```

흐름을 풀어보면 이래요. 처음 한 번 `codegraph init` 명령으로 프로젝트를 훑으면, 트리시터(tree-sitter, 코드를 구조적으로 분석해주는 도구)가 소스 파일을 읽어 함수·클래스·호출 관계를 뽑아내고, 그걸 SQLite(가벼운 파일 기반 데이터베이스)에 저장해요. 이후 AI 도우미는 파일을 직접 뒤지는 대신 이 데이터베이스에 "이 함수를 누가 부르고 있어?" 같은 질문을 던져 즉시 답을 받아요. 코드를 수정하면 운영체제(OS)의 파일 변경 이벤트를 감지해서 그래프도 자동으로 갱신돼요.

### 5. 처음 보는 용어 풀이

- **지식 그래프 (knowledge graph)** — 코드 안의 요소들(함수, 클래스 등)을 점으로, 그 관계(누가 누구를 부른다, 누가 누구를 상속한다)를 선으로 그린 지도예요. AI가 이 지도를 보면 코드 구조를 빠르게 파악할 수 있어요.

- **MCP 서버 (Model Context Protocol server)** — AI 도우미와 외부 도구를 연결해주는 표준 통로예요. CodeGraph는 이 통로를 통해 클로드 코드 같은 AI에게 "검색", "호출자 찾기" 같은 기능을 도구로 제공해요.

- **토큰 (token)** — AI 모델이 글자를 처리하는 최소 단위. 보통 비용도 토큰 수로 계산되기 때문에, 토큰을 적게 쓰는 게 곧 비용 절감으로 이어져요.

- **도구 호출 (tool call)** — AI가 작업을 하면서 외부 기능(파일 읽기, 검색 등)을 부르는 행위. 호출 횟수가 많을수록 시간과 토큰이 더 들어요.

- **트리시터 (tree-sitter)** — 여러 프로그래밍 언어의 소스 코드를 구조적인 형태(추상 구문 트리, AST)로 바꿔주는 파서 라이브러리. CodeGraph는 이걸 이용해 함수·클래스 같은 요소를 정확히 뽑아내요.

- **FTS5 (Full-Text Search 5)** — SQLite에 내장된 전체 텍스트 검색 기능. 코드 안에서 이름으로 빠르게 심볼을 찾을 때 사용돼요.

- **임팩트 분석 (impact analysis)** — 어떤 함수나 클래스를 고치면 어디까지 영향이 번지는지 미리 따져보는 기능. 수정 전에 안전성을 확인할 때 유용해요.

- **익스플로어 에이전트 (Explore agent)** — 클로드 코드가 큰 질문에 답할 때 자동으로 띄우는 보조 AI. 원래는 이 보조들이 파일을 잔뜩 뒤져서 토큰을 많이 쓰는데, CodeGraph는 이들이 그래프를 먼저 보도록 안내해요.

### 6. 한 발 더 들어가고 싶다면

- [colbymchenry/codegraph 저장소](https://github.com/colbymchenry/codegraph) — 설치 명령, 지원 언어 목록, CLI 옵션 같은 1차 자료를 확인할 수 있어요.
- [tree-sitter 공식 사이트](https://tree-sitter.github.io/) — CodeGraph가 코드 구조를 뽑아낼 때 쓰는 파서 도구가 어떻게 동작하는지 살펴볼 수 있어요.
- [npm의 @colbymchenry/codegraph 패키지](https://www.npmjs.com/package/@colbymchenry/codegraph) — npm으로 설치하거나 버전 변경 내역을 추적하고 싶을 때 보면 좋아요.


마음이 바뀌었나요? 명령 하나로 CodeGraph가 설정한 모든 에이전트에서 제거됩니다:

인스톨러의 역작업을 수행합니다 — 설정된 각 에이전트에서 CodeGraph의 MCP 서버 설정, 지침, 권한을 제거합니다. 프로젝트 인덱스(`.codegraph/`)는 그대로 유지됩니다. 프로젝트별로 제거하려면 `codegraph uninit`을 사용하세요. `--target`으로 특정 에이전트에서만 제거하거나, `--yes`로 비대화형 실행이 가능합니다.

## CodeGraph를 사용하는 이유

Claude Code가 코드베이스를 탐색할 때, grep·glob·Read로 파일을 스캔하는 **Explore 에이전트**를 생성하며 — 도구 호출마다 토큰을 소비합니다.

**CodeGraph는 그 에이전트들에게 사전 인덱싱된 지식 그래프를 제공합니다** — 심벌 관계, 호출 그래프, 코드 구조. 에이전트는 파일을 스캔하는 대신 그래프를 즉시 조회합니다.

### 벤치마크 결과

7개 언어에 걸친 **7개의 실제 오픈소스 코드베이스**를 대상으로 테스트하여, 에이전트(Claude Code, 헤드리스)가 아키텍처 질문 하나에 답할 때 CodeGraph **사용 시**와 **미사용 시**를 비교했습니다. 각 셀은 **암(arm)당 4회 실행의 중앙값**에서의 절감량입니다.

> **평균: 35% 비용 절감 · 59% 토큰 감소 · 49% 속도 향상 · 70% 도구 호출 감소**

| 코드베이스 | 언어 | 비용 | 토큰 | 시간 | 도구 호출 |
| --- | --- | --- | --- | --- | --- |
| **VS Code** | TypeScript · ~10k 파일 | 35% 절감 | 73% 감소 | 41% 단축 | 72% 감소 |
| **Excalidraw** | TypeScript · ~600 | 47% 절감 | 73% 감소 | 60% 단축 | 86% 감소 |
| **Django** | Python · ~2.7k | 34% 절감 | 64% 감소 | 59% 단축 | 81% 감소 |
| **Tokio** | Rust · ~700 | 52% 절감 | 81% 감소 | 63% 단축 | 89% 감소 |
| **OkHttp** | Java · ~640 | 17% 절감 | 41% 감소 | 36% 단축 | 64% 감소 |
| **Gin** | Go · ~150 | 22% 절감 | 23% 감소 | 34% 단축 | 19% 감소 |
| **Alamofire** | Swift · ~100 | 38% 절감 | 59% 감소 | 51% 단축 | 77% 감소 |

효과는 코드베이스 크기에 비례합니다. 대형 저장소에서는 에이전트가 **파일 읽기 없이** 몇 번의 호출만으로 인덱스에서 답을 도출하는 반면, CodeGraph가 없을 때는 에이전트가 grep/find/Read(그리고 자신이 생성하는 하위 에이전트들)로 팬아웃됩니다. Gin(~150 파일)처럼 소규모 저장소에서는 네이티브 검색이 이미 저렴하므로 효과 차이가 줄어듭니다.

**전체 벤치마크 상세 내용**

**방법론.** 각 암은 `--strict-mcp-config`와 함께 저장소에 대해 헤드리스로 실행되는 `claude -p`(Claude Opus 4.7, Claude Code v2.1.145)입니다. **WITH** = CodeGraph MCP 서버 활성화, **WITHOUT** = 빈 MCP 설정. 기본 제공 Read/Grep/Bash는 양쪽 모두 사용 가능. 저장소당 동일한 질문, **암당 4회 실행, 중앙값 보고**. 비용 = 실행의 `total_cost_usd`; 토큰 = 처리된 전체 토큰(캐시 포함 입력 + 출력); 시간 = 실제 경과 시간; 도구 호출 = 모델이 생성한 하위 에이전트 내부 호출 포함 모든 도구 호출. 저장소는 `--depth 1`로 클론하고, 동일한 CodeGraph 빌드로 인덱싱하여 서빙.

| VS Code | "익스텐션 호스트는 메인 프로세스와 어떻게 통신하는가?" |
| Excalidraw | "Excalidraw는 캔버스 요소를 어떻게 렌더링하고 업데이트하는가?" |
| Django | "Django ORM은 QuerySet에서 쿼리를 어떻게 빌드하고 실행하는가?" |

| Alamofire | $0.61 → $0.99 | 1.1M → 2.6M | 1m 19s → 2m 41s | 15 → 64 |

**CodeGraph가 효과적인 이유:** 인덱스가 있을 때 에이전트는 직접 답합니다 — 영역을 파악하는 `codegraph_context`, 관련 소스를 위한 `codegraph_explore` 한 번, 그리고 종료, 보통 파일 읽기 없음. 인덱스가 없을 때는 에이전트(그리고 생성하는 Explore 하위 에이전트)가 올바른 코드를 읽기 전에 대부분의 예산을 탐색(find/ls/grep)에 소비합니다. CodeGraph는 _직접_ 쿼리될 때만 효과가 있으므로, 지침은 에이전트가 탐색을 파일 읽기 하위 에이전트에 위임하지 않고 직접 답하도록 유도합니다 — 그렇지 않으면 하위 에이전트가 어차피 파일을 읽어 CodeGraph가 오버헤드가 됩니다.

## 프레임워크 인식 라우트

CodeGraph는 웹 프레임워크 라우팅 파일을 감지하고, `route` 노드를 생성하여 `references` 엣지로 해당 핸들러 클래스 또는 함수와 연결합니다. 뷰/컨트롤러의 호출자를 조회하면 이제 이를 바인딩하는 URL 패턴이 함께 표시됩니다.

| 프레임워크 | 인식 형태 |
| --- | --- |
| **Django** | `urls.py`의 `path()`, `re_path()`, `url()`, `include()` (CBV `.as_view()`, 점 경로) |
| **Flask** | `@app.route('/path', methods=[...])`, 블루프린트 라우트 |
| **FastAPI** | `@app.get(...)`, `@router.post(...)`, 모든 표준 메서드 |
| **Express** | 미들웨어 체인을 포함한 `app.get(...)`, `router.post(...)` |
| **NestJS** | `@Controller` + `@Get/@Post/...`, GraphQL `@Resolver` + `@Query/@Mutation`, `@MessagePattern`/`@EventPattern`, `@SubscribeMessage` |
| **Laravel** | `Route::get()`, `Route::resource()`, `Controller@action`, 튜플 문법 |
| **Drupal** | `*.routing.yml` 라우트(`_controller`, `_form`, 엔티티 핸들러); `.module`/`.theme`/`.install`/`.inc`의 `hook_*` 구현 |
| **Rails** | `get '/x', to: 'users#index'`, 해시 로켓 `=>` 문법 |
| **Spring** | 메서드의 `@GetMapping`, `@PostMapping`, `@RequestMapping` |
| **Gin / chi / gorilla / mux** | `r.GET(...)`, `router.HandleFunc(...)` |
| **Axum / actix / Rocket** | `.route("/x", get(handler))` |
| **ASP.NET** | 액션 메서드의 `[HttpGet("/x")]` 속성 |
| **Vapor** | `app.get("x", use: handler)` |
| **React Router** / **SvelteKit** | 라우트 컴포넌트 노드 |

## 빠른 시작

### 1. 인스톨러 실행

```bash
npx @colbymchenry/codegraph
```

인스톨러가 수행하는 작업:

- 설정할 에이전트를 선택 — 설치된 에이전트 자동 감지: **Claude Code**, **Cursor**, **Codex CLI**, **opencode**, **Hermes Agent**
- PATH에 `codegraph`를 설치할지 묻기 (에이전트가 MCP 서버를 실행하는 데 필요)
- 설정을 모든 프로젝트에 적용할지 현재 프로젝트에만 적용할지 묻기
- 선택한 각 에이전트의 MCP 서버 설정 + 지침 파일 작성 (예: `CLAUDE.md`, `.cursor/rules/codegraph.mdc`, `~/.codex/AGENTS.md`)
- Claude Code가 대상 중 하나인 경우 자동 허용 권한 설정
- 현재 프로젝트 초기화 (로컬 설치 시에만)

**비대화형 (스크립팅 / CI):**

```bash
codegraph install --yes                              # 에이전트 자동 감지, 전역 설치
codegraph install --target=cursor,claude --yes       # 명시적 대상 목록
codegraph install --target=auto --location=local     # 감지된 에이전트, 프로젝트 로컬
codegraph install --print-config codex               # 스니펫 출력, 파일 쓰기 없음
```

| 플래그 | 값 | 기본값 |
| --- | --- | --- |
| `--target` | `auto`, `all`, `none`, 또는 csv (`claude,cursor,...`) | 프롬프트 |
| `--location` | `global`, `local` | 프롬프트 |
| `--yes` | (boolean) | 각 단계마다 프롬프트 |
| `--no-permissions` | (boolean) Claude 자동 허용 목록 건너뜀 | 권한 활성화 |
| `--print-config <id>` | 에이전트 하나의 스니펫을 출력하고 종료 | — |

## 동작 원리

```
┌─────────────────────────────────────────────────────────────────┐
│                        Claude Code                               │
│                                                                  │
│  "사용자 인증 구현"                                               │
│           │                                                      │
│           ▼                                                      │
│  ┌─────────────────┐      ┌─────────────────┐                   │
│  │  Explore Agent  │ ──── │  Explore Agent  │                   │
│  └────────┬────────┘      └────────┬────────┘                   │
│           │                        │                             │
└───────────┼────────────────────────┼─────────────────────────────┘
            │                        │
            ▼                        ▼
┌───────────────────────────────────────────────────────────────────┐
│                     CodeGraph MCP Server                          │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐               │
│  │   Search    │  │   Callers   │  │   Context   │               │
│  │  "auth"     │  │  "login()"  │  │  for task   │               │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘               │
│         │                │                │                       │
│         └────────────────┼────────────────┘                       │
│                          ▼                                        │
│              ┌───────────────────────┐                            │
│              │   SQLite Graph DB     │                            │
│              │   • 387 symbols       │                            │
│              │   • 1,204 edges       │                            │
│              │   • Instant lookups   │                            │
│              └───────────────────────┘                            │
└───────────────────────────────────────────────────────────────────┘
```

1. **추출 (Extraction)** — [tree-sitter](https://tree-sitter.github.io/)가 소스 코드를 AST로 파싱합니다. 언어별 쿼리가 노드(함수, 클래스, 메서드)와 엣지(호출, 임포트, 상속, 구현)를 추출합니다.

2. **저장 (Storage)** — 모든 데이터가 FTS5 전문 검색을 갖춘 로컬 SQLite 데이터베이스(`.codegraph/codegraph.db`)에 저장됩니다.

3. **해석 (Resolution)** — 추출 후 참조가 해석됩니다: 함수 호출 → 정의, 임포트 → 소스 파일, 클래스 상속, 프레임워크별 패턴.

4. **자동 동기화 (Auto-Sync)** — MCP 서버가 네이티브 OS 파일 이벤트로 프로젝트를 감시합니다. 변경 사항은 디바운스(2초 정지 구간)되고, 소스 파일만 필터링되며, 증분 동기화됩니다. 코딩 중에도 그래프가 최신 상태를 유지합니다 — 설정 불필요.

## CLI 참조

```bash
codegraph                         # 대화형 인스톨러 실행
codegraph install                 # 인스톨러 실행 (명시적)
codegraph uninstall               # 에이전트에서 CodeGraph 제거 (install의 역작업)
codegraph init [path]             # 프로젝트에서 초기화 (--index로 인덱싱도 함께)
codegraph uninit [path]           # 프로젝트에서 CodeGraph 제거 (--force로 프롬프트 건너뜀)
codegraph index [path]            # 전체 인덱스 (--force로 재인덱싱, --quiet으로 출력 최소화)
codegraph sync [path]             # 증분 업데이트
codegraph status [path]           # 통계 표시
codegraph query <search>          # 심벌 검색 (--kind, --limit, --json)
codegraph files [path]            # 파일 구조 표시 (--format, --filter, --max-depth, --json)
codegraph context <task>          # AI용 컨텍스트 빌드 (--format, --max-nodes)
codegraph callers <symbol>        # 함수/메서드를 호출하는 것 찾기 (--limit, --json)
codegraph callees <symbol>        # 함수/메서드가 호출하는 것 찾기 (--limit, --json)
codegraph impact <symbol>         # 심벌 변경 시 영향받는 코드 분석 (--depth, --json)
codegraph affected [files...]     # 변경 사항에 영향받는 테스트 파일 찾기 (아래 참조)
codegraph serve --mcp             # MCP 서버 시작
```

### `codegraph affected`

변경된 소스 파일에 영향받는 테스트 파일을 찾기 위해 임포트 의존성을 재귀적으로 추적합니다.

```bash
codegraph affected src/utils.ts src/api.ts         # 파일을 인수로 전달
git diff --name-only | codegraph affected --stdin   # git diff에서 파이프
codegraph affected src/auth.ts --filter "e2e/*"     # 커스텀 테스트 파일 패턴
```

| 옵션 | 설명 | 기본값 |
| --- | --- | --- |
| `--stdin` | stdin에서 파일 목록 읽기 | `false` |
| `-d, --depth <n>` | 최대 의존성 탐색 깊이 | `5` |
| `-f, --filter <glob>` | 테스트 파일 식별을 위한 커스텀 glob | 자동 감지 |
| `-j, --json` | JSON으로 출력 | `false` |
| `-q, --quiet` | 파일 경로만 출력 | `false` |

**CI/훅 예시:**

```bash
#!/usr/bin/env bash
AFFECTED=$(git diff --name-only HEAD | codegraph affected --stdin --quiet)
if [ -n "$AFFECTED" ]; then
  npx vitest run $AFFECTED
fi
```

## MCP 도구

MCP 서버로 실행 시, CodeGraph는 Claude Code에 다음 도구를 노출합니다:

| 도구 | 목적 |

| `codegraph_search` | 코드베이스 전반에서 이름으로 심벌 찾기 |
| `codegraph_context` | 태스크를 위한 관련 코드 컨텍스트 빌드 |
| `codegraph_callers` | 함수를 호출하는 것 찾기 |
| `codegraph_callees` | 함수가 호출하는 것 찾기 |
| `codegraph_impact` | 심벌 변경 시 영향받는 코드 분석 |
| `codegraph_node` | 특정 심벌에 대한 세부 정보 조회 (선택적으로 소스 코드 포함) |
| `codegraph_explore` | 한 번의 호출로 관련 심벌 여러 개의 소스를 파일별로 그룹화하여 반환, 관계 맵 포함 |
| `codegraph_files` | 인덱싱된 파일 구조 조회 (파일시스템 스캔보다 빠름) |
| `codegraph_status` | 인덱스 상태 및 통계 확인 |

## 라이브러리 사용법

```javascript
import CodeGraph from '@colbymchenry/codegraph';

const cg = await CodeGraph.init('/path/to/project');
// 또는: const cg = await CodeGraph.open('/path/to/project');

await cg.indexAll({
  onProgress: (p) => console.log(`${p.phase}: ${p.current}/${p.total}`)
});

const results = cg.searchNodes('UserService');
const callers = cg.getCallers(results[0].node.id);
const context = await cg.buildContext('fix login bug', { maxNodes: 20, includeCode: true, format: 'markdown' });
const impact = cg.getImpactRadius(results[0].node.id, 2);

cg.watch();   // 파일 변경 시 자동 동기화
cg.unwatch(); // 감시 중지
cg.close();
```

## 설정

설정이 없습니다 — CodeGraph는 제로 설정입니다. [지원 언어](https://github.com/colbymchenry/codegraph#supported-languages)에 매핑되는 확장자를 가진 모든 파일을 인덱싱하며 **`.gitignore`를 준수합니다**: git 저장소에서는 git 자체를 통해, 비 git 프로젝트에서는 `.gitignore` 파일(루트 및 중첩, git과 동일한 방식)을 직접 읽어 처리합니다.

실제로 의미하는 바:

- git이 무시하는 모든 것 — `node_modules`, 빌드 출력물, `.env`의 시크릿 — 은 인덱싱되지 않습니다. **그래프에서 제외하려면 `.gitignore`에 추가하세요.**
- 작성하거나 동기화해야 할 설정 파일이 없으며, 언어별로 설정할 것도 없습니다: 지원은 파일 확장자에 따라 자동으로 이루어집니다.
- 1 MB보다 큰 파일은 건너뜁니다(생성된 번들, 압축 JS, 벤더 바이너리) — 유용한 심벌 없이 파싱 예산만 소비하기 때문입니다.

> gitignore에 없는 커밋된 파일은 `vendor/`나 커밋된 `dist/` 아래에 있더라도 _인덱싱됩니다_. 그래프에 포함하고 싶지 않은 의존성이나 빌드 디렉터리를 커밋했다면 `.gitignore`에 추가하세요.

## 문제 해결

**"CodeGraph not initialized"** — 먼저 프로젝트 디렉터리에서 `codegraph init`을 실행하세요.

**인덱싱이 느림** — `node_modules` 및 기타 대형 디렉터리가 제외되어 있는지 확인하세요. `--quiet`을 사용하여 출력 오버헤드를 줄이세요.

**MCP에서 `database is locked` 발생** — 현재 빌드에서는 발생하지 않아야 합니다: CodeGraph는 자체 Node 런타임을 번들로 포함하고, WAL 모드에서 Node의 내장 `node:sqlite`를 사용하므로 동시 읽기가 쓰기에 의해 차단되지 않습니다. 그래도 발생한다면:

- **구버전(0.9 이전) 설치 상태입니다.** 번들 런타임을 받기 위해 재설치하세요 — `curl -fsSL https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.sh | sh` (macOS/Linux), `irm https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.ps1 | iex` (Windows), 또는 `npm i -g @colbymchenry/codegraph@latest`.
- **`codegraph status`에서 `Journal:`이 `wal` 외의 값을 표시합니다** — 이 파일시스템에서 WAL을 활성화할 수 없음(네트워크 공유 및 WSL2 `/mnt`에서 흔함)으로 읽기가 쓰기에 의해 차단될 수 있습니다. 프로젝트(`.codegraph/` 폴더 포함)를 로컬 디스크로 이동하세요.

**MCP 서버가 연결되지 않음** — 프로젝트가 초기화/인덱싱되었는지 확인하고, MCP 설정의 경로를 검증하고, 커맨드라인에서 `codegraph serve --mcp`가 동작하는지 확인하세요.

**심벌 누락** — MCP 서버는 저장 시 자동 동기화됩니다(몇 초 기다리세요). 필요 시 `codegraph sync`를 수동으로 실행하세요. 파일의 언어가 지원되는지, 설정 패턴에 의해 제외되지 않았는지 확인하세요.
