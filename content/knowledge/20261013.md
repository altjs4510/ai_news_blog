## 📌 학습 정리

### 1. 한 줄로 말하면
다른 앱에서 마음에 드는 기능을 봤을 때 그 앱의 설계도(소스 코드)가 없어도 AI 비서가 앱을 직접 뜯어보고 "이 기능은 이렇게 돌아가요"라고 근거와 함께 설명해 주는 도구예요. 원하면 비슷한 기능을 내 프로젝트에 만들어 주는 데까지 이어집니다.

### 2. 왜 이게 만들어졌어요?
AI 에이전트(agent)는 지금까지 주로 새 코드를 쓰는 데 쓰였어요. 에이전트는 스스로 도구를 골라 쓰면서 일을 단계별로 처리하는 AI 비서를 말해요. 그런데 이미 나와 있는 앱이 "어떻게" 동작하는지 알아내는 건 완전히 다른 일이에요. 소스 코드가 없으면 컴퓨터만 읽을 수 있는 실행 파일을 거꾸로 해석해야 하는데, 이걸 역분석, 흔히 리버스 엔지니어링(reverse engineering)이라고 불러요. 이 작업은 Hopper, Ghidra, IDA 같은 전문 분석 도구를 다룰 줄 알아야 해서 진입 장벽이 꽤 높았어요. REA는 이런 분석 도구들을 에이전트와 이어 줘서, 사람은 질문만 던지고 에이전트가 도구를 돌려 결과를 해석하도록 만든 거예요.

### 3. 비유로 풀면
요리 탐정에 비유해 볼 수 있어요. 레시피 없이 맛있는 요리 한 접시만 받은 상황에서 성분 분석기, 현미경, 온도계 같은 장비를 들고 "이 소스엔 뭐가 들어갔고 몇 도에서 익혔는지"를 하나씩 확인하는 거예요. 그리고 "이 부분은 분석 결과로 확인됐고, 이 부분은 아직 모르겠어요"라고 근거를 붙여 보고하는 탐정이죠. REA에서는 에이전트가 탐정, 여러 분석 도구가 장비 역할을 해요.

그래서 결국 REA는 에이전트가 앱을 직접 열어 확인하고, 거기서 나온 증거를 바탕으로 설명하거나 비슷한 기능을 다시 만들게 해 주는 도구 상자예요.

### 4. 어떻게 작동하는지 (그림으로)

```mermaid
flowchart TD
    A[사용자: '노트 앱의 검색 기능이 어떻게 돌아가는지 알려줘'] --> B[AI 에이전트가 질문을 이해함]
    B --> C[연결 규격을 통해 REA 도구 호출]
    C --> D[내 컴퓨터 안에서 앱 분석<br/>실행 파일 · 자바스크립트 앱 · 웹사이트 등]
    D --> E[결과 돌려받기<br/>코드 조각 · 참조 관계 · 아직 모르는 부분]
    E --> F{더 알아볼 게 있나?}
    F -- 있다 --> C
    F -- 충분하다 --> G[동작 방식 설명 + 근거 제시]
    G --> H[내 프로젝트에 비슷한 기능 구현하고 테스트]
```

사용자가 질문하면 에이전트가 REA의 분석 도구를 불러서 대상 앱을 살펴봐요. REA는 찾아낸 코드와 참조 관계, 그리고 "아직 확인 못 한 부분"까지 함께 돌려줘요. 에이전트는 이 결과를 보고 더 파고들지 판단하고, 이 과정을 몇 번 반복한 뒤 설명이나 구현으로 넘어가요. 분석은 내 컴퓨터 안에서 이뤄지고, 같은 기능을 터미널 명령어로 직접 써 볼 수도 있어요.

### 5. 처음 보는 용어 풀이
- **기계어로 된 실행 파일 (native binary)** — 사람이 쓴 코드를 컴퓨터가 바로 실행할 수 있게 바꿔 둔 파일이에요. 사람이 읽기 어려워서 전용 분석 도구가 있어야 속을 볼 수 있어요.
- **흉내 낸 코드 (pseudocode)** — 실행 파일을 거꾸로 해석해서 "대략 이런 코드였을 것"이라고 다시 써 놓은 코드예요. 원래 코드와 똑같진 않지만 동작을 이해하는 데 도움이 돼요.
- **어셈블리어 (assembly)** — 기계어를 사람이 겨우 읽을 수 있게 바꾼, 아주 낮은 수준의 명령어 목록이에요. 흉내 낸 코드보다 정확하지만 읽기는 훨씬 어려워요.
- **에이전트와 도구를 잇는 연결 규격 (MCP)** — AI 에이전트가 외부 도구를 불러 쓸 수 있게 해 주는 공통 연결 방식이에요. REA는 이 방식으로 Claude Code, Codex, Cursor, Gemini CLI 같은 여러 에이전트에 붙어요.
- **분석 엔진 (provider: Hopper · Ghidra · IDA)** — 실행 파일을 깊이 분석하는 전문 프로그램들이에요. REA가 이걸 대신 실행해 주지만, 프로그램 자체는 각자 합법적으로 설치하고 라이선스를 갖춰야 해요.
- **Electron 앱과 프로세스 간 통신 (IPC)** — Electron은 웹 기술로 데스크톱 앱을 만드는 틀이에요. 이런 앱은 화면 담당 부분과 뒤에서 실제 일을 처리하는 부분이 나뉘어 있고, 그 둘이 메시지를 주고받는 통로를 IPC라고 불러요.
- **명령줄 도구 (CLI)** — 마우스 대신 터미널에 명령어를 입력해서 쓰는 방식이에요. REA는 에이전트 없이도 `rea` 명령어로 같은 분석을 돌릴 수 있어요.

### 6. 한 발 더 들어가고 싶다면
- [REA 웹사이트](https://rea.tools/) — 설치 방법, 그림이 있는 안내서, 실제 분석 사례를 한곳에서 볼 수 있어요.
- [Notion 사례 연구](https://rea.tools/showcase/notion/) — Notion 앱에서 복사·붙여넣기 기능이 화면 쪽에서 앱 내부까지 어떤 경로로 전달되는지 따라가 볼 수 있어요.

## 📖 원문 전체 번역 (정독용)

> 의역 최소화한 전체 번역입니다. 큰 흐름은 위 정리에서 잡고, 정확한 워딩이 필요할 땐 이 섹션에서 정독하세요.

* * *

만들고 싶은 기능이 어떤 앱에 있나요? 에이전트에게 REA로 조사해 달라고 요청하세요. REA는 소스 코드 없이 앱을 살펴보고, 기능이 어떻게 동작하는지 설명하고, 근거를 보여 주고, 여러분의 프로젝트에 맞는 버전을 만들어 줍니다.

REA는 에이전트를 네이티브 바이너리, JavaScript 및 Electron 앱, .NET 어셈블리, 웹사이트를 검사하는 도구에 연결합니다. 같은 도구를 터미널에서도 사용할 수 있습니다. 분석은 로컬에서 실행되며, 결과에는 각 결론의 근거와 한계가 함께 포함됩니다.

설정(setup)은 REA를 에이전트에 등록하고, 그에 맞는 워크플로우 지침을 설치합니다. 네이티브 분석에는 이미 설치된 Hopper, Ghidra, IDA를 사용할 수 있으며, 설정 과정에서 승인을 받아 Hopper를 선택적으로 설치할 수도 있습니다. 정적 JavaScript 분석에는 네이티브 분석 엔진이 필요하지 않습니다.

> **[REA 웹사이트](https://rea.tools/)** 에서 설치 방법, 그림이 들어간 가이드, 실제 사례 연구를 확인하세요.

## 빠른 시작

[](https://github.com/morluto/rea#quick-start)
### 에이전트 설정

[](https://github.com/morluto/rea#set-up-your-agent)
Node.js와 npm이 설치되어 있다면 다음을 실행하세요.

npx rea-agents setup

사용할 에이전트를 선택하고, 제안된 변경 사항을 검토한 뒤 승인하세요. 설정은 기존 구성의 백업과 함께 REA의 MCP 서버와 그에 맞는 워크플로우 지침을 추가합니다. 이후 에이전트를 재시작하세요.

설정은 Claude Code, Codex, Cursor, Gemini CLI, Grok Build 및 [기타 에이전트](https://github.com/morluto/rea/blob/main/docs/installation.md#supported-agents)를 지원합니다. 프로바이더 구성과 수동 MCP 등록은 [설치 및 설정](https://github.com/morluto/rea/blob/main/docs/installation.md)을 참고하세요.

### 에이전트에게 요청하기

[](https://github.com/morluto/rea#ask-your-agent)

```
Understand how search works in the Notes app, show me the evidence, and build a
similar feature for my project.
```

Notes를 분석하려는 대상 앱으로, 검색을 이해하려는 기능으로 바꿔서 사용하세요.

### 터미널 사용

[](https://github.com/morluto/rea#use-the-terminal)
추출된 JavaScript/Electron 앱 디렉터리 또는 ASAR을 검사합니다.

npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

결과에는 모듈, import, Electron 경계와 그 근거가 포함됩니다. 경로를 분석 대상으로 바꾸세요(예: Windows에서는 `"D:/apps/example"`).

`rea` 명령을 정기적으로 사용하도록 설치하려면 다음을 실행하세요.

npm install --global rea-agents
rea --help

네이티브 분석을 하려면 먼저 프로바이더를 구성하세요. 네이티브 명령, 프로바이더 선택, 스냅샷, 스크립팅은 [CLI 및 Evidence 가이드](https://github.com/morluto/rea/blob/main/docs/cli.md)를 참고하세요.

### REA 업데이트

[](https://github.com/morluto/rea#update-rea)
REA는 빠르게 변화하며, 새 릴리스에는 잦은 버그 수정이 포함됩니다. 설치본을 최신 상태로 유지하세요.

`npm install --global` 또는 `bun add --global`로 설치한 CLI의 경우:

rea update

Bun 전역 업데이트에는 Bun 1.2.17 이상이 필요합니다. 더 오래된 Bun을 사용 중이라면 `rea update`를 실행하기 전에 Bun을 수동으로 업그레이드하세요.

에이전트 등록과 스킬을 새로 고치려면 업데이트가 출력한 setup 명령을 실행하세요.

`npx`를 사용한다면 다음으로 에이전트 설정을 업데이트하세요.

npx rea-agents@latest setup

설정 변경 사항을 검토하고 에이전트를 재시작하세요. 일회성 CLI 명령에는 `npx rea-agents@latest` 뒤에 명령을 붙여 사용하세요. Bun에서는 `npx rea-agents@latest` 대신 `bunx rea-agents@latest`를 사용하세요.

## REA의 동작 방식

[](https://github.com/morluto/rea#how-rea-works)
에이전트는 MCP를 통해 REA를 호출하여 대상을 검사하고 관련 코드를 추적합니다. REA는 발견 사항을 근거와 함께 반환합니다. 에이전트는 이를 사용해 후속 질문을 하거나, 동작을 설명하거나, 구현을 작성하고 테스트합니다. CLI 명령도 동일한 워크플로우를 사용합니다.

## 분석 가능한 대상

[](https://github.com/morluto/rea#what-you-can-analyze)
REA에는 Node.js 22.x (>=22.19), 24.x (>=24.11) 또는 26+ 와 npm이 필요합니다. 추가 도구와 호스트 지원 여부는 대상에 따라 다릅니다.

| 대상 | REA가 반환하는 것 | 요구 사항 및 가이드 |
| --- | --- | --- |
| 네이티브 바이너리 | 의사코드(pseudocode), 어셈블리, 문자열, 심볼, 호출 및 참조 | Hopper, Ghidra 또는 IDA; [네이티브 분석](https://rea.tools/guides/native/) |
| 오프라인 ELF 레이아웃 | 섹션, 세그먼트, 원본 심볼/재배치, 정적 보호 기법(mitigation) 후보 | Linux x64에서 호출자가 제공하는 pwntools; [바이너리 진단](https://github.com/morluto/rea/blob/main/docs/binary-diagnostics.md) |
| Go 바이너리 | 내장된 컴파일러 버전, 모듈, 대체(replacement) 및 빌드 설정 | 내장 정적 ELF/PE/thin Mach-O 검사; Go 설치 불필요 |
| WASM 아티팩트 | 검증, 섹션, 정확한 import/export WAT 형식 및 디코딩된 WAT | 호출자가 제공하는 WABT 1.0.42; `inspect_wasm_artifact` |
| EVM 바이트코드 | 디스패치 셀렉터, 바이트 오프셋, 추론된 인자 및 가변성(mutability) | Linux x64의 로컬 raw/hex 캐리어; [오프라인 EVM 가이드](https://github.com/morluto/rea/blob/main/docs/evm-bytecode.md) |
| 기록된 Linux 크래시 | 원시 노트, 기록된 모든 스레드의 레지스터/시그널, 선택적 매핑 후보 | Linux x64에서 호출자가 제공하는 pwntools; 선택적 GDB/pwndbg; [기록된 크래시](https://github.com/morluto/rea/blob/main/docs/recorded-crashes.md) |
| JavaScript / Electron | 모듈, import, 소스 맵, 라우트, IPC 및 네이티브 애드온 관계 | Node.js 및 npm; [애플리케이션 분석](https://rea.tools/guides/javascript/) |
| 웹사이트 | 페이지 구조, 스크립트, 네트워크 관찰 결과 및 요청한 스크린샷 | Chrome 계열 브라우저; [브라우저 분석](https://rea.tools/guides/browser/) |
| 저장된 네트워크 캡처 | 요청, 응답, 노출된 페이로드 및 소스 위치 | HAR; 네이티브 mitmproxy 캡처의 경우 Linux의 mitmdump; [캡처 가이드](https://github.com/morluto/rea/blob/main/docs/web-network-captures.md) |
| .NET 어셈블리 | 메타데이터, CIL 명령어, 선언된 네이티브 의존성 및 빌드 비교 | 없음(정적 분석만); [관리 코드 가이드](https://github.com/morluto/rea/blob/main/docs/managed-code-analysis.md) |
| Android APK | 매니페스트 선언, 클래스, 디컴파일된 메서드 및 참조 | Linux/macOS/Windows x64의 헤드리스 JADX 및 전체 JDK; [Android 가이드](https://github.com/morluto/rea/blob/main/docs/android-analysis.md) |
| Android 기기 | 기기, 패키지, 프로세스, 로그, 덤프, 화면 캡처, APK/파일 전송 | 호출자가 제공하는 adb(에뮬레이터 또는 실기기); [ADB 가이드](https://github.com/morluto/rea/blob/main/docs/adb-device-analysis.md) |
| JEB 프로젝트 | 엔진 기반 프로젝트 유닛, 아티팩트 다이제스트, 타입/메서드 의사코드 | MCP를 제공하는, 호출자가 시작한 JEB 클라이언트(REA_JEB_MCP_URL로 선택); [JEB 가이드](https://github.com/morluto/rea/blob/main/docs/jeb-analysis.md) |
| Android 리소스 | 디코딩된 매니페스트, 문자열 테이블, 로캘 및 버전 정보 | 호출자가 제공하는 Apktool 런처; [리소스 가이드](https://github.com/morluto/rea/blob/main/docs/apktool-resource-analysis.md) |
| Flutter 앱 | Dart 스냅샷 해시, ABI별 라이브러리 다이제스트 및 엔진 빌드 출처(provenance) | 없음(정적 APK 파싱); [Flutter 가이드](https://github.com/morluto/rea/blob/main/docs/flutter-analysis.md) |
| 펌웨어 | 영역, 추출 결과 및 네이티브 분석 핸드오프 | Linux의 Binwalk / Unblob; [펌웨어 가이드](https://github.com/morluto/rea/blob/main/docs/firmware-analysis.md) |
| 패키지 및 리소스 | 파일 인벤토리, 다이제스트, plist, Apple 번들 구조 및 추출된 리소스 | [아티팩트 및 JavaScript 가이드](https://github.com/morluto/rea/blob/main/docs/javascript-artifact-reconstruction.md), [Apple 애플리케이션](https://github.com/morluto/rea/blob/main/docs/apple-application-analysis.md) |
| 프로세스 동작 | 터미널 출력, 상호작용, 종료 및 파일 시스템 관찰 결과, 실행 간 비교 | 네이티브 PTY가 있는 Linux/macOS; [프로세스 캡처](https://github.com/morluto/rea/blob/main/docs/process-capture.md) |

정적 JavaScript 및 .NET 검사는 애플리케이션을 실행하지 않고 제공된 파일을 읽습니다. 런타임 캡처는 사용자 권한으로 선택한 대상을 실행하거나 상호작용합니다. 각 런타임 가이드에 그 영향이 설명되어 있습니다.

네이티브 포맷과 호스트 지원은 프로바이더에 따라 다릅니다. [Hopper 및 Ghidra 설정](https://github.com/morluto/rea/blob/main/docs/installation.md#hopper), [IDA 가이드](https://github.com/morluto/rea/blob/main/docs/ida-provider.md), [실험적 Windows Ghidra 지원](https://github.com/morluto/rea/blob/main/docs/windows-ghidra-p0.md)을 참고하세요. Ghidra는 [16비트 DOS 분석](https://github.com/morluto/rea/blob/main/docs/ghidra-dos.md)도 지원합니다. 큰 바이너리의 경우 `REA_GHIDRA_STARTUP_TIMEOUT_MS` 또는 `REA_HOPPER_STARTUP_TIMEOUT_MS`로 프로바이더의 시작 제한 시간을 늘리세요. 프로바이더 선택은 [CLI 가이드](https://github.com/morluto/rea/blob/main/docs/cli.md#choose-a-provider)를 참고하세요. 최신 npm 릴리스 이후 추가된 기능은 [릴리스 제공 여부](https://github.com/morluto/rea/blob/main/docs/installation.md#released-package-and-main)를 확인하세요.

## FAQ

[](https://github.com/morluto/rea#faq)

**어떤 에이전트가 REA를 사용할 수 있나요?**
로컬 MCP 서버를 지원하는 모든 에이전트입니다. 설정은 [지원되는 에이전트](https://github.com/morluto/rea/blob/main/docs/installation.md#supported-agents)를 구성하며, 다른 클라이언트는 [수동 MCP 등록](https://github.com/morluto/rea/blob/main/docs/installation.md#mcp-registry)을 사용할 수 있습니다.

**Hopper, Ghidra 또는 IDA가 필요한가요?**
심층 네이티브 분석에는 이 중 하나를 사용합니다. 정적 JavaScript 및 .NET 검사는 네이티브 분석 엔진 없이 동작합니다. 설정은 승인 후 Hopper를 설치할 수 있으며, Ghidra와 IDA는 기존 설치본을 사용합니다. [프로바이더 설정](https://github.com/morluto/rea/blob/main/docs/installation.md#hopper)을 참고하세요.

**Hopper를 먼저 실행해야 하나요?**
작업에 Hopper가 필요하면 REA가 Hopper를 시작합니다. macOS에서는 첫 실행 시 대화상자가 나타나 데모 모드를 선택하거나 라이선스를 활성화하도록 요청할 수 있습니다. 첫 CLI/MCP 작업 또는 무인 작업 전에 같은 사용자 세션에서 해당 프롬프트를 완료하세요. 필요하면 Hopper를 수동으로 여세요. [Hopper 시작 및 문제 해결](https://github.com/morluto/rea/blob/main/docs/installation.md#launcher-paths-and-troubleshooting)을 참고하세요.

**skills.sh에서 스킬을 설치하면 무엇이 되나요?**
스킬은 에이전트에 조사 지침을 제공합니다. REA의 MCP 서버를 등록하고 그에 맞는 지침을 설치하려면 `npx rea-agents setup`을 사용한 뒤 에이전트를 재시작하세요. [스킬 단독 설치](https://github.com/morluto/rea/blob/main/docs/installation.md#skill-only-installation)를 참고하세요.

**REA는 어떤 코드를 반환하나요?**
네이티브 분석은 의사코드와 어셈블리를 반환합니다. JavaScript/Electron 분석은 모듈과 그 관계를 복원합니다. 에이전트는 이 발견 사항을 사용해 구현을 작성하고 테스트합니다. [쇼케이스](https://github.com/morluto/rea#showcases)에 실제 예시가 있습니다.

**REA가 내 앱을 업로드하나요?**
REA는 대상을 로컬에서 분석합니다. 에이전트가 도구 결과를 받으며, 해당 모델 제공자에게는 자체 데이터 정책이 있습니다.

**버그를 만나면 어떻게 해야 하나요?**
먼저 업데이트하세요. 최근 릴리스에서 이미 수정되었을 수 있습니다.

`npm install --global` 또는 `bun add --global`로 설치한 CLI의 경우:

rea update

`npx`를 통한 에이전트 설정의 경우:

npx rea-agents@latest setup

에이전트를 사용 중이라면 [설정 새로 고침](https://github.com/morluto/rea#update-rea)을 완료하고 에이전트를 재시작하세요. 같은 작업을 다시 시도하세요. 문제가 계속되면 REA 버전, 대상 유형, 재현 단계, 오류 출력을 포함해 [이슈를 등록](https://github.com/morluto/rea/issues)하세요.
