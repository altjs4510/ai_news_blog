## 📌 학습 정리

### 1. 한 줄로 말하면

AI에게 코드 검토를 통째로 맡기지 않고 일을 둘로 나눈 도구예요. 어떤 파일을 볼지, 어떤 기준으로 볼지, 지적을 몇 번째 줄에 붙일지는 정해진 절차가 챙기고, 판단이 필요한 부분만 AI가 맡아요. 알리바바 사내에서 2년 동안 수만 명의 개발자가 쓰면서 수백만 건의 코드 결함을 찾아낸 도구를 누구나 쓸 수 있게 공개한 거예요.

### 2. 왜 이게 만들어졌어요?

요즘은 Claude Code 같은 범용 AI 코딩 도우미에게 "이 변경 좀 검토해 줘" 하고 코드 검토(code review)를 맡기는 경우가 많아요. 그런데 원문을 보면 이렇게 쓸 때 반복되는 불편이 세 가지 있다고 해요. 변경된 파일이 많으면 AI가 일부만 골라 보고 나머지는 건너뛰기도 해요. 지적한 줄 번호나 파일이 실제 위치와 어긋나기도 하고, AI에게 주는 지시문(prompt)을 조금만 바꿔도 검토 품질이 크게 흔들려요. 원문은 그 원인을 "말로만 지시하는 구조라서 검토 과정에 단단한 제약이 없기 때문"이라고 봐요. 그래서 틀리면 안 되는 단계는 프로그램 로직이 책임지고 AI는 잘하는 일에만 집중하도록 역할을 나눴어요.

### 3. 비유로 풀면

출판사에서 원고를 교정하는 과정과 비슷해요. 먼저 편집 데스크가 이번에 바뀐 페이지를 빠짐없이 뽑아요. 그다음 서로 관련 있는 페이지는 한 묶음으로 묶어서 교정자 여러 명에게 나눠줘요. 예를 들면 같은 문구의 영어판과 중국어판 페이지 같은 것들이요. 묶음마다 그 원고에 맞는 체크리스트도 붙여 주고요.

교정자는 자기 묶음을 읽다가 필요하면 원고 전체나 다른 장을 찾아보면서 판단해요. 마지막에는 따로 확인하는 담당자가 빨간 펜 표시가 정확한 줄에 붙었는지, 지적 내용이 맞는지 한 번 더 봐요.

그래서 결국 누락이나 위치 착오처럼 실수하기 쉬운 '행정 업무'는 절차가 맡고, 교정자 역할인 AI는 코드를 읽고 판단하는 일에만 머리를 쓰는 구조예요.

### 4. 어떻게 작동하는지 (그림으로)

```mermaid
flowchart TD
    A["코드 변경 내역 읽기"] --> B["검토할 파일 정확히 고르기<br/>(필요 없는 파일은 걸러냄)"]
    B --> C["관련 파일끼리 한 묶음으로<br/>(예: 영어·중국어 메시지 파일)"]

    D --> E3["묶음 N 담당 AI"]

    E2 --> F
    E3 --> F
    F --> G["줄 단위로 정확한 검토 코멘트"]

    classDef rule fill:#e3f0ff,stroke:#5b8def
    classDef ai fill:#ffe9d6,stroke:#e8894a
```

파란 칸(파일 고르기, 묶기, 규칙 붙이기, 위치·내용 재점검)은 규칙대로 도는 프로그램이 맡아요. 주황 칸만 대규모 언어 모델(LLM)을 쓰는 AI가 맡고요. 각 AI는 자기 묶음을 따로 검토하는데, 필요하면 파일 전체를 열어 보거나 프로젝트 코드를 검색하고 다른 변경 파일도 참고하면서 판단해요. 비교할 변경 내역이 없는 낯선 코드는 파일 전체를 훑는 모드(`ocr scan`)로 검토할 수 있어요.

### 5. 처음 보는 용어 풀이

- **코드 변경 내역 (diff)**: 이전 버전과 비교해서 어떤 줄이 추가·삭제·수정됐는지 보여주는 기록이에요. 이 도구는 코드 변경 이력을 관리하는 도구인 Git이 만든 변경 내역을 읽는 데서 검토를 시작해요.
- **에이전트 (agent)**: 지시를 받으면 필요한 도구를 스스로 골라 쓰면서 일을 처리하는 AI 프로그램이에요. 여기서는 파일을 읽고 코드를 검색하면서 변경된 부분의 맥락을 파악하는 역할을 해요.
- **결정적 처리 (deterministic engineering)**: 같은 입력이 들어오면 늘 같은 결과가 나오는, 규칙대로 움직이는 프로그램 로직이에요. 틀리면 안 되는 단계를 여기에 맡겨서 AI 답변이 흔들리는 문제를 줄여요.
- **하위 에이전트 (sub-agent)**: 큰 일을 쪼갠 조각 하나만 전담하는 작은 AI 작업자예요. 묶음끼리 맥락을 섞지 않고 따로 돌기 때문에 변경이 아주 커도 안정적이고, 여러 묶음을 동시에 검토할 수도 있어요.
- **정밀도 (Precision)와 재현율 (Recall)**: 정밀도는 AI가 문제라고 짚은 것 중 진짜 결함의 비율이고, 재현율은 실제 결함 중 AI가 찾아낸 비율이에요. 원문 벤치마크를 보면 같은 모델을 쓴 Claude Code보다 정밀도와 종합 점수(F1)는 높고 재현율은 낮았어요. 헛경보를 줄이려고 일부러 택한 균형이라고 해요.
- **토큰 (token)**: AI가 글을 읽고 쓸 때 쪼개는 단위예요. 쓴 만큼 비용이 나가요. 원문에 따르면 Claude Code보다 토큰을 약 9분의 1만 쓰면서 검토도 더 빨리 끝냈다고 해요.
- **위임 모드 (Delegation Mode)**: 파일 고르기와 규칙 정리는 이 도구가 하고, 실제 검토는 내가 이미 쓰는 AI 코딩 도우미가 자기 모델로 하는 방식이에요. 이 모드에서는 이 도구에 AI 모델을 따로 설정할 필요가 없어요.

### 6. 한 발 더 들어가고 싶다면

- [alibaba/open-code-review 저장소](https://github.com/alibaba/open-code-review): 설치 명령(`npm install -g @alibaba-group/open-code-review`)과 기본 사용법을 볼 수 있어요. 한국어를 포함한 여러 언어 안내문도 있어요.
- [공식 문서 (open-codereview.ai/docs)](https://open-codereview.ai/docs): 검토 규칙을 입맛대로 바꾸는 법을 볼 수 있어요. Claude Code·Codex·Cursor 같은 코딩 도우미와 연결하는 법, 코드를 올릴 때마다 자동으로 검사하는 흐름(CI/CD)에 붙이는 법도 있어요.
- AACR-Bench 데이터셋 (Hugging Face): 원문에는 이름만 나오고 주소는 없어서, Hugging Face에서 이 이름으로 찾아보시면 돼요. 인기 오픈소스 저장소 50개에서 실제 코드 변경 요청(Pull Request) 200건을 모았고, 10개 언어에 걸쳐 시니어 엔지니어 80여 명이 결함 정답 1,505건을 표시했어요. 이 벤치마크가 어떻게 만들어졌는지 알 수 있어요.

## Open Code Review란 무엇인가?

Open Code Review는 AI 기반 코드 리뷰 CLI 도구다. 이 프로젝트는 알리바바 그룹(Alibaba Group) 내부의 공식 AI 코드 리뷰 어시스턴트로 시작했다 — 지난 2년간 수만 명의 개발자에게 서비스를 제공했고 수백만 건의 코드 결함을 발견했다. 대규모 환경에서 철저히 검증을 거친 뒤, 우리는 이를 커뮤니티를 위한 오픈소스 프로젝트로 발전시켰다. 모델 엔드포인트만 설정하면 바로 시작할 수 있다.

이 도구는 Git diff를 읽고, 변경된 파일들을 도구 사용(tool-use) 능력을 갖춘 에이전트를 통해 설정 가능한 LLM에 전달하며, 라인 단위 정밀도를 갖춘 구조화된 리뷰 코멘트를 생성한다. 이 에이전트는 파일 전체 내용을 읽고, 코드베이스를 검색하고, 다른 변경 파일들을 맥락 파악을 위해 살펴볼 수 있어 단순한 표면적인 diff 피드백이 아닌 심층 리뷰를 만들어낸다. diff 리뷰 외에도, `ocr scan`은 낯선 코드베이스나 의미 있는 diff가 없는 디렉토리를 감사하기 위해 전체 파일을 리뷰한다.

자세한 내용은 [공식 웹사이트](https://open-codereview.ai)를 방문하라.

## 벤치마크

동일한 기반 모델을 사용할 때, Open Code Review는 범용 에이전트(Claude Code)와 비교해 **Precision(정밀도)**과 **F1**에서 훨씬 높은 성능을 달성하면서도 **토큰 소비량은 약 1/9 수준**에 그치고 리뷰 완료 속도도 더 빠르다. 다만 Recall(재현율)은 범용 에이전트보다 낮은데, 이는 노이즈보다 정밀도를 우선하기 위한 의도적인 트레이드오프다.

이는 인기 있는 오픈소스 저장소 **50개**, 실제 Pull Request **200개**, 프로그래밍 언어 **10개**로 구성된 실전 코드 리뷰 벤치마크이며, 80명 이상의 시니어 엔지니어가 교차 검증했다(정답 라벨링된 이슈 **1,505개**).

[Hugging Face에서 AACR-Bench 데이터셋을 살펴보라](https://huggingface.co/datasets).

| 지표 | 측정 대상 | 중요한 이유 |
|---|---|---|
| F1 | 정밀도와 재현율의 조화 평균 | 전반적인 리뷰 품질을 나타내는 최적의 단일 지표 |
| Precision | 보고된 이슈 중 실제 결함의 비율 | 높을수록 걸러내야 할 오탐(false alarm)이 적음 |
| Recall | 실제 결함 중 발견된 비율 | 높을수록 리뷰를 통과해 새어나가는 이슈가 적음 |
| Avg Time | 리뷰당 실제 소요 시간 | CI 파이프라인 지연시간에 영향 |
| Avg Token | 리뷰당 소비되는 총 토큰 수 | API 비용에 직접적인 영향 |

## Open Code Review를 쓰는 이유

### 범용 에이전트의 문제

Skills 기능을 갖춘 Claude Code 같은 범용 에이전트를 코드 리뷰에 써본 적이 있다면, 다음과 같은 고충을 겪었을 가능성이 높다:

- **불완전한 커버리지** — 변경 규모가 클수록 에이전트는 "지름길을 택하는" 경향이 있어, 일부 파일만 선택적으로 리뷰하고 나머지는 놓친다.
- **위치 드리프트(position drift)** — 보고된 이슈가 실제 코드 위치와 자주 일치하지 않으며, 라인 번호나 파일 참조가 목표 지점에서 벗어난다.
- **불안정한 품질** — 자연어에 의존하는 Skills는 디버깅이 어렵고, 프롬프트의 미세한 변화만으로도 리뷰 품질이 크게 요동친다.

근본 원인은, 순전히 언어 모델에만 의존하는 아키텍처는 리뷰 과정에 대한 엄격한 제약(hard constraints)을 갖고 있지 않다는 데 있다.

### 핵심 설계: 결정적 엔지니어링 × 에이전트의 하이브리드

Open Code Review의 핵심 철학은 결정적 엔지니어링(deterministic engineering)과 에이전트를 결합해, 각각이 가장 잘하는 일을 맡게 하는 것이다.

#### 결정적 엔지니어링 — 하드 제약

**절대 틀려서는 안 되는** 리뷰 단계에서는, 언어 모델이 아니라 엔지니어링 로직이 정확성을 보장한다:

- **정밀한 파일 선정** — 어떤 파일을 리뷰해야 하고 어떤 파일을 걸러내야 하는지를 정확히 결정해, 중요한 변경 사항이 누락되지 않도록 보장한다.
- **스마트 파일 번들링** — 관련 파일들을 하나의 리뷰 단위로 묶는다(예: `message_en.properties`와 `message_zh.properties`가 함께 번들링된다). 각 번들은 격리된 컨텍스트를 가진 서브 에이전트로 실행되며 — 이는 매우 큰 변경 규모에서도 안정성을 유지하고 자연스럽게 동시 리뷰를 지원하는 분할 정복(divide-and-conquer) 전략이다.
- **세밀한 규칙 매칭** — 각 파일의 특성에 맞는 리뷰 규칙을 매칭해, 모델의 주의(attention)를 날카롭게 집중시키고 정보 노이즈를 원천에서 제거한다. 순전히 언어에 의존하는 규칙 안내 방식과 비교했을 때, 템플릿 엔진 기반의 규칙 매칭이 더 안정적이고 예측 가능하다.
- **외부 위치 지정 및 반영(reflection) 모듈** — 독립적인 코멘트 위치 지정 모듈과 코멘트 반영 모듈이 AI 피드백의 위치 정확도와 내용 정확도를 체계적으로 개선한다.

#### 에이전트 — 동적 의사결정

에이전트의 강점은 가장 중요한 지점, 즉 동적 의사결정과 동적 맥락 검색에 집중되어 있다:

- **시나리오 맞춤형 프롬프트** — 코드 리뷰에 맞춰 깊이 최적화된 프롬프트 템플릿으로, 효과를 높이면서도 토큰 소비를 줄인다.
- **시나리오 맞춤형 툴셋** — 대규모 프로덕션 데이터에서 도구 호출 트레이스를 심층 분석해 추출했다 — 호출 빈도 분포, 도구별 반복 호출률, 신규 도구가 전체 호출 체인에 미치는 영향까지 포함 — 그 결과, 범용 에이전트 툴킷보다 코드 리뷰에 더 안정적이고 예측 가능한 전용 툴셋이 만들어졌다.

## 사용 방법

### 사전 요구사항

**Git >= 2.41** — Open Code Review는 diff 생성, 코드 검색, 저장소 조작에 Git을 사용한다.

### CLI

#### 설치

```
npm install -g @alibaba-group/open-code-review
```

설치가 끝나면 `ocr` 명령을 전역에서 사용할 수 있다.

다른 설치 방법(설치 스크립트, GitHub Release 바이너리, 소스에서 빌드)은 [Installation](https://open-codereview.ai/docs)을 참조하라.

### 빠른 시작

#### 1. LLM 설정

[Delegation Mode](https://open-codereview.ai/docs)를 사용하지 않는 한, 코드를 리뷰하기 전에 LLM을 설정해야 한다.

```
ocr config provider
# 내장 provider를 선택하거나 커스텀 provider를 추가

ocr config model
# 활성 provider에 사용할 모델을 선택
```

대화형 UI가 provider 선택, API 키 입력, 모델 설정을 안내한 뒤 자동으로 연결 테스트를 수행한다.

CLI 설정, 환경 변수, 커스텀 provider 및 기타 고급 설정은 [Configuration](https://open-codereview.ai/docs)을 참조하라.

#### 2. 리뷰

```
cd your-project
# 워크스페이스 모드 — staged, unstaged, untracked 변경 사항을 모두 리뷰
ocr review

# 브랜치 범위 — feature-branch가 main에서 분기된 이후의 변경 사항을 리뷰 (merge-base 모드)
ocr review --from main --to feature-branch

# 단일 커밋
ocr review --commit abc123

# 중단된 범위/커밋 리뷰 재개
ocr session list
ocr review --from main --to feature-branch --resume <session-id>

# 전체 파일 스캔 — diff가 아니라 파일 전체를 리뷰 (git 히스토리 불필요)
ocr scan
# 저장소 전체를 스캔

ocr scan --path internal/agent
# 디렉토리 또는 특정 파일들을 스캔

ocr scan --resume <session-id>
# 중단된 전체 파일 스캔 재개

# 결과를 파일로 저장 (AI 호스트 에이전트에 권장)
ocr review --format json --output result.json

# Delegation 모드 — AI 코딩 에이전트가 직접 리뷰를 수행하도록 함
# OCR이 파일 선정과 규칙 해석을 처리하며, LLM 설정이 필요 없음
ocr delegate preview
ocr delegate rule src/main.go src/handler.go
```

## 문서

전체 문서는 [open-codereview.ai/docs](https://open-codereview.ai/docs)에 있다:

- **Quickstart** — 설치 및 첫 리뷰 실행
- **Installation** — 모든 플랫폼과 패키지 매니저
- **CLI Reference** — 모든 명령과 플래그
- **Review Rules** — 경로 필터링 및 타겟팅으로 리뷰 규칙 커스터마이징
- **Configuration** — 설정 키와 환경 변수
- **MCP Server** — 외부 도구로 리뷰 에이전트 확장
- **Coding Agent Integrations** — 사용 중인 플랫폼 선택
  - **Claude Code** — 리뷰 슬래시 명령이 포함된 플러그인 설치
  - **Codex** — 호출 가능한 리뷰 스킬이 포함된 플러그인 설치
  - **Cursor** — 이식 가능한 리뷰 스킬이 포함된 플러그인 설치
  - **OpenCode** — 네이티브 리뷰 도구 및 슬래시 명령 설치
  - **QCA Forward** — QCA 호스트 모델과 즉시 배포 가능한 템플릿으로 Delegation 모드 실행
  - **Skill-compatible agents** — 이식 가능한 에이전트 스킬 설치
- **Review Execution Modes** — 연동 이후, 어떤 LLM이 리뷰를 수행할지 선택
  - **Default (OCR-managed)** — OCR이 설정된 자체 LLM으로 리뷰 수행
  - **Delegation Mode** — 사용자의 코딩 에이전트가 자체 LLM으로 리뷰 수행; OCR API 키 불필요
- **CI/CD Integration** — GitHub Actions, GitLab CI, GitFlic CI, Gerrit 연동
- **Session Viewer** — 브라우저에서 리뷰 세션을 탐색·재생하고, 코멘트를 수정 완료/무시로 표시해 발견된 이슈를 처리하는 동안 숨길 수 있음
- **Telemetry** — 관측성(observability)을 위한 OpenTelemetry 연동
- **FAQ** — 자주 묻는 질문 및 트러블슈팅
